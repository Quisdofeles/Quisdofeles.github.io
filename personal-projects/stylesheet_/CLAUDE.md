## 1. What this app is

**Stylesheet_** (displayed exactly like that, with the trailing underscore) is a Windows desktop app made by HALFWIT Studios. It is a fast brand sketchbook that sits next to Figma and Illustrator. It does not replace them.

The user imports finished vectors (SVGs from Illustrator), fonts, and colors, arranges them into simple block-based layouts, duplicates those layouts into side-by-side variations with different palettes or fonts, and exports flat PNG/JPEG reference images to send to clients or to color-pick from in Figma/Illustrator.

Core use case (a client logo job):
1. Designer builds a black-and-white logo mark in Illustrator with each part on a **named layer**. The wordmark is NOT baked into the SVG.
2. Imports the SVG into Stylesheet_. Drops a canvas into the preview, adds the vector block, a title block (wordmark), and a caption block (tagline).
3. Duplicates the canvas ~5 times, gives each a different set of colors. Exports with style labels. Client replies "Option C".
4. Locks in C's colors on every canvas, swaps the title font on each instead. Exports again. Client picks.
5. Builds the final, exports large (4×) as a reference for the real brand work elsewhere.

It will be offered as a **free download** on the HALFWIT Studios website, so it must work for people other than the author.

## 5. Architecture rules

### 5.1 Single source of truth
All app data lives in **one state object** in `state.js`. Nothing else holds its own copy.

- Modules **read** state and **render** from it.
- Modules **change** state only through functions exported by `state.js` (e.g. `addBlock()`, `updateBlock()`, `selectNode()`), which then notify subscribers.
- After any change, every panel that depends on it re-renders. Simple full re-renders of a panel are fine — performance is not a concern at this scale. Clarity is.
- The preview and the layers tree are two views of the same data. Dragging onto the preview and editing in the editor both call the same state functions. **They can never disagree.**

### 5.2 Undo
`state.js` keeps a history stack of state snapshots (max 50). A snapshot is a deep copy of **the canvases, the selection, and the whole library (including the trash list)**, so deleting a library item is undoable. Zoom/pan, export settings and UI collapse state are NOT part of history. `Ctrl+Z` undoes, `Ctrl+Shift+Z` / `Ctrl+Y` redoes (ignored while typing in an input). Slider drags and text typing push one history entry per gesture (the first tick), and the next gesture starts a new one (`endGesture()` on the input's `change` event). Because undo/redo replace `state.library` and `state.session.canvases` wholesale, modules must never cache those objects.

Subscribers receive a `meta` object: `{ library, session, live, view, selection, ui, exportSettings, history, refresh }`. Panels skip re-rendering for irrelevant flags (e.g. `view` only updates the zoom transform; `live` slider ticks don't rebuild the properties panel). `requestRender()` redraws everything without changing data (used after fonts/vectors finish loading). "Empty trash" is not undoable and clears the history.

### 5.3 Electron security
- `contextIsolation: true`, `nodeIntegration: false`, `sandbox: true`.
- The renderer never touches Node or `fs` directly. Everything goes through `window.api` defined in `preload.js` using `contextBridge` + `ipcRenderer.invoke`.
- Imported files are served to the renderer through a custom protocol **`ssfile://`** registered in `main.js` (privileged, `supportFetchAPI: true`, `standard: true`, `secure: true`, plus `corsEnabled: true` so `fetch()` from the `file://` page can read imported files) that maps only into the app's library folder. Reject any path that resolves outside it. URL form: `ssfile://lib/fonts/<fileName>` and `ssfile://lib/vectors/<fileName>` (the host is always `lib`; responses carry `access-control-allow-origin: *`).
- `index.html` has a Content-Security-Policy meta tag: only the app's own files and `ssfile:` (scripts: self only).

### 5.4 window.api (preload)
```
window.api = {
  loadLibrary(), saveLibrary(data),
  loadSession(), saveSession(data),
  importFiles(),               // opens a file dialog, copies chosen files into the library folder, returns metadata
  readLibraryFile(relPath),    // returns text (used for SVG contents)
  saveExport(dataUrl, format), // opens save dialog, writes the image
  openLibraryFolder(),
  window: { minimize(), toggleMaximize(), close(), isMaximized(), onMaximizeChange(cb) },
  onBeforeQuit(cb)             // lets the renderer flush the autosave before the app closes (cb may return a promise)

  // Added beyond the original spec:
  syncTrash(files),            // files = [{subdir, fileName}] that SHOULD be in library/trash; main moves files so disk matches (also moves unlisted trash files back = restore/undo)
  purgeTrashFiles(files),      // permanently deletes those files from library/trash (empty trash)
  readBundledFont(name),       // base64 of a bundled UI font in src/fonts (whitelisted ttf names) so exports can embed IBM Plex Mono
  getVersion()                 // app version from package.json
}
```
`importFiles()` returns `[{kind:'font'|'vector', subdir, fileName, originalName, ext}]`; stored file names are `<timestamp><rand>_<original name>` so two files with the same name never collide.

## 6. Persistence (no projects, no file names)

There are **no projects, no Save As, no file names.** The app holds one working session.

App data lives in Electron's `app.getPath('userData')`:
```
userData/
├─ library.json        # fonts, colors, palettes, vectors, presets
├─ session.json        # canvases, selection, zoom/pan, export settings
└─ library/
   ├─ fonts/           # copied font files
   ├─ vectors/         # copied SVGs and raster images
   └─ trash/           # soft-deleted files (trash/fonts/, trash/vectors/); the list of trashed items lives in library.json
```

- **Importing copies files in.** The user's originals can be moved or deleted without breaking anything.
- **Autosave:** session saves 1 second after the last change (debounced), and always on close (the window's `close` event is held until the renderer flushes both files, with a 2-second timeout fallback). Library saves immediately on change.
- **Soft delete (trash):** every library delete (right-click → delete, always behind a confirm dialog) moves the item into `library.trash` and, for fonts and vectors, moves its file into `library/trash/`. Nothing is permanently removed until the user chooses "empty trash" in Settings. Undo (Ctrl+Z) or "restore" in Settings puts it back. `persistence.js` keeps the folder in sync with the list after every library change (and on startup, to self-heal), and the app waits for that sync before reloading restored files.
- Write JSON atomically (write to a `.tmp` file, then rename) so a crash never corrupts data.
- **Never bundle user fonts in the installer.** The installer ships with an empty library (plus default presets).

## 7. Data model

```js
library = {
  fonts:    [{ id, family, fileName, style, weight }],   // one entry per font FILE; UI groups by family. style: 'normal'|'italic'; weight: number (e.g. 700)
  colors:   [{ id, name, hex }],                          // name is lowercase_with_underscores by default
  palettes: [{ id, name, colors: [{ id, name, hex }] }],  // any number of colors
  vectors:  [{ id, name, fileName, kind: 'svg'|'image', layers: ['mark', 'accent', ...] }],   // name = original file name (e.g. mark.svg)
  presets:  [{ id, name, structure: <canvas without any assigned fonts/colors/vectors> }],
  trash:    [{ id, kind: 'font'|'color'|'palette'|'vector'|'preset'|'palette_color', item, deletedAt }]
            // soft-deleted items; `item` is the original entry (palette_color: {paletteId, index, color})
}

session = {
  canvases: [canvas, ...],
  selectedId: null | blockId,
  zoom: 1, pan: { x: 0, y: 0 },          // pan is an offset from where the grid sits at rest (24px in, 100px down)
  export: { styleLabels: true, format: 'png'|'jpeg', transparent: true, scale: 2 },
  collapsedGroups: { roles: true, ... },  // editor property groups the user collapsed (roles, type, layout, block)
  collapsedNodes: { <nodeId>: true },     // layers-tree nodes the user collapsed
  helpSeen: false                         // false until the help overlay has been shown once
}

canvas = {
  id, type: 'canvas', name: 'lockup_A',
  roles: { background, primary, secondary, accent },        // hex values
  fonts: { title, heading, subheading, body, caption },      // LIBRARY FONT IDS (a specific file = family + weight + style), or null. Not family names.
  layout: { direction: 'stack'|'row', gap: 24, align: 'center' },
  aspect: 0.889,                                             // width / height; default 8/9 (matches the mockup). business_card 1.75, social_post 0.8
  hidden: false,
  children: [block, ...]
}

block = {
  id, type, name, hidden: false,
  // text blocks (title, heading, subheading, body, caption):
  text: 'NORTHFIELD', size: 32, colorRole: 'primary',
  fontOverride: null /* library font id */, colorOverride: null,
  // vector block:
  vectorId, width: 120, layerRoles: { mark: 'primary', inner: 'secondary', dot: 'accent' }, layerOverrides: {},
  //   (an SVG with no named layers uses the single key '*' for the whole drawing: layerRoles: { '*': 'primary' })
  // image block: vectorId (kind 'image'), width
  // swatch block: shows the canvas's role colors as chips
  // spacer block: size
  // group block (a nested container): layout + children, inherits roles/fonts from its canvas
}
```

### Roles cascade (like CSS variables)
Blocks never store fixed colors or fonts by default. They point to a **role**:
- A text block of type `title` uses `canvas.fonts.title` (a library font id; if that font is missing/deleted or the block's text is empty, it renders the gray placeholder showing the type name) and `canvas.roles[block.colorRole]`. Each library font file is registered under its own CSS family `ssf-<fontId>` and rendered at `font-weight: normal` (the weight lives in the file), so there is never faux bold.
- **Font choice = family + weight/style.** The type picker lists families; choosing one (or dropping a family card) assigns the weight **closest to 400** (normal style preferred, a tie goes to the heavier weight). A weight/style selector next to the picker then switches among that family's files. Fonts are shown as `Space Grotesk 700` / `DM Serif Display 400 italic`.
- A vector block colors each named layer with `canvas.roles[layerRoles[layerName]]`.
- The canvas background is `canvas.roles.background`.
- Any block can set an **override** (a specific hex or font) that beats the role. Overrides show a small "reset" button in the editor.
- Changing a canvas's role recolors everything in it at once. That is the core feature.

### Presets
"Save as preset" stores the selected canvas's **structure only**: block types, order, nesting, names, sizes, layout, and which roles each block points to. It strips all hex values, font names, vector references, and text overrides. When a preset is dropped in, empty slots render as **gray placeholders** (a gray box where the vector goes, the block's type name as placeholder text in IBM Plex Mono).

Ship these default presets: `symmetrical_logo` (vector over title over caption, stacked, centered), `horizontal_lockup` (vector left of a stacked title + caption, row), `type_hierarchy` (title, heading, subheading, body, caption stacked, left aligned), `business_card`, `social_post`. (`business_card` = row with vector + stacked title/caption/body at aspect 1.75; `social_post` = stack with vector, title, body, caption at aspect 0.8. Their exact structures were invented and can be revised.) Preset-created text blocks start with empty text (so they show placeholders until the user types).

First launch ships: the 5 presets, 8 starter colors (`ink`, `paper`, `signal_orange`, `harbor_blue`, `midnight`, `sun_gold`, `forest`, `slate`), two starter palettes (`warm_signal`, `night_harbor`), and one empty canvas `lockup_A`.

### 8.5 Library panel (left)

**Height rule:** the six sections share the panel's height using flex. 4. **palettes** — `+` button in header (creates `palette_N` with one gray color and starts renaming). Each palette is a card: name on top (double-click to rename), then a **5-column grid of swatches that wraps** for any number of colors, ending in a `+` tile that adds a color. 5. **blocks** — 2-column grid of small cards with a lime glyph + name: `title`, `heading`, `subheading`, `body`, `caption`, `vector`, `image`, `swatch`, `canvas`, `spacer`, `group`.
6. **presets** — dashed-border rows: `▣ symmetrical_logo`, etc.

Scrollbars: 6px, thumb `#3A3A41`, transparent track. **On hover of that scroll area the thumb turns lime.**

**Deleting library items (any section):** right-click → `delete` → **always a confirm dialog**. If the item is in use, the dialog says how many blocks use it (fonts: text blocks resolving to that font; vectors: vector/image blocks). Confirming moves the item to the trash (see section 6); blocks that used it fall back to their gray placeholder (and re-link if the item is restored). Deletes are one undo step (Ctrl+Z). Colors, palettes and presets store copies of values, so they are never "in use" and deleting them changes no canvas.

**SVG import rule:** on import, parse the SVG, find named groups (`<g id="...">` — Illustrator exports layer names as ids). Those names become `layers`. If no named groups exist, show a small non-blocking notice: "no named layers found — this vector will take one color." Sanitize every SVG: remove `<script>`, `<foreignObject>`, event handler attributes, and external references.

Implementation details (`svg.js`): layers are the **outermost** named `<g>` groups; a single wrapper group that contains several named groups is skipped. Generic Illustrator ids (`Layer_1`, `Artboard_2`, `XMLID_3_`, `_x31_`…) don't count as named. Also removed: `<iframe>`, `<object>`, `<embed>`, `<image>`, audio/video, `javascript:` values, and any `href`/`url()` that isn't an in-file `#id`. The original file on disk is never modified: sanitizing and preparing happens **every time a vector is loaded** (cached in memory per vector id). Preparation: layer groups get `data-layer="<id>"`; inside layers, non-`none` fills are stripped and strokes become `currentColor`; `<style>` rules are scoped per vector (`svg[data-vid="…"] .cls-1`) so classes from different SVGs can't collide; other ids are prefixed per vector; a `viewBox` is guaranteed and fixed width/height removed. At render time each layer group gets `fill` and `color` set to its role color. Layer display names decode Illustrator's `_x20_` escapes. Raster images (`kind: 'image'`) render as `<img>` and don't recolor.

**Font import:** family, weight and style are read from the font's own `name` and `OS/2` tables (TTF, OTF, WOFF; WOFF is inflated with `DecompressionStream`). WOFF2 can't be read in the browser and falls back to guessing from the file name. A variable font imports as one entry at its default weight.

### 8.6 Preview panel (middle)

Never set manually. Each canvas is **384px wide at 100% zoom** (height = width ÷ `aspect`), 20px gap; the same constants are used by the export. Canvas labels are `OPTION A/B/C…` by position among visible canvases. When the number of visible canvases changes, the view auto-`fit`s (not on ordinary edits). `fit` never zooms past 100%.

A selected block gets a thin dashed lime outline. Double-clicking the zoom percentage resets to 100%. The dot grid zooms and pans with the canvases.
- Empty slots/missing assets render as **gray placeholders** (gray box for vector/image, gray chip with the type name for text).
- **Floating export bar** at the bottom, same style as the top bar: `include style labels` checkbox, `format` PNG|JPEG segmented toggle, a **transparent background icon toggle** (checkerboard icon; lime border + lime icon when on, gray when off; disabled and shown off when JPEG is selected since JPEG can't be transparent), `scale` 1×|2×|4× segmented toggle, and the lime `export` button aligned to the far right.

### 8.7 Editor panel (right)
Header: `03 — EDITOR`.

**Height rule:** the editor is a flex column that exactly fills the panel. The **layers list is the only part that scrolls** and it absorbs all leftover height (`flex: 1; min-height: 120px; overflow-y: auto`). The properties area below it never scrolls, so it must stay compact: 36px control rows, and each property group (`roles`, `type`, `layout`, block-specific controls) has a collapsible header (▾/▸, all open by default, collapse state saved in the session). The `save as preset` button is pinned to the bottom. Verify everything fits at a 1280×720 window with all groups open; if it doesn't, tighten spacing before anything else.

**As built:** at window heights ≤820px the row height drops from 36px to 26px (`--row-h`), and slider rows are one line (label, slider, value); direction and align toggles share one line; the text block's font/color overrides share one "override" row. This fits all groups open in the typical case (2 text roles + a text block selected). **Known exception:** with 5 text roles + a text block selected at 720px tall, `#props` is allowed to scroll (~50px) rather than shrink the layers list below its 120px minimum (`#props { flex: 0 1 auto; overflow-y: auto }`). This is the one place the "never scrolls" rule is bent.

**layers** (with `+ block` on the right, which opens a small menu of block types):
- A tree. Canvases at the top level with ▾/▸ carets to expand/collapse. Children indented 20px per level.
- Each row: icon glyph + name, and a muted tag on the right (`canvas`, `3 layers`, `title`, `caption`…).
- Selected row: `#1A1A1E` background, 1px lime outline, its tag turns lime.
- Hover shows an **eye icon** to hide/show the block (hidden blocks are dimmed in the tree and not rendered).
- Double-click a name to rename. Drag rows to reorder or move into another canvas/group (top/bottom quarter of a row = before/after, middle of a group row = into it; canvases only reorder among canvases).
- `Delete` removes the selected node, `Ctrl+D` duplicates it (duplicating a canvas copies everything, including roles, and auto-names it with the first free letter, e.g. `lockup_B`). Both are undoable and ignored while typing in an input.
- Selecting a node in the preview expands any collapsed ancestors in the tree. `+ block` adds to the selected container (or after the selected block); with nothing selected it creates a new canvas containing the block.

**Properties** (below a divider) — contents depend on what's selected:
- **Canvas or anything inside it** shows the canvas's **roles** (background, primary, secondary, accent) as a **2×2 grid** of compact buttons, each with a swatch, role name, and hex. Click opens a color picker popover listing library colors and palettes plus a hex input. Dropping a color onto a role row sets it.
- **type**: one row per text role used in that canvas (`title`, `caption`, …): a family button with ▾ (opens the family picker) plus a weight/style selector (`400`, `700`, `400 italic`; disabled when the family has one file). A missing/deleted font shows `missing ▾`. A font can also be dropped on the row.
- **layout** (canvas/group, or the container around a selected block): `stack` | `row` segmented toggle, align (start/center/end) on the same line, `gap` slider (0–120px).
- **Text block selected**: text content input (live, one undo step per edit), size slider (8–200), color role picker (primary/secondary/accent; choosing a role clears the color override), and one "override" row: font override (family + weight) and color override, each with a `reset` link once set.
- **Vector block selected**: width slider, and one row per named layer (or one "whole vector" row) letting you choose its role (select) or an override hex (with reset). **Image** block: width. **Spacer**: size.
- Bottom: dashed `save as preset ▣` button (asks for a name in a small inline input).

## 9. Drag and drop

Uses native HTML5 drag and drop. The drag payload is `{ kind: 'font'|'color'|'vector'|'block'|'preset'|'node', id }` (`node` = a row of the layers tree; `font` id = a specific library font file; `block` id = the block type name). Sources carry `data-drag-kind` / `data-drag-id`; `dragdrop.js` plans each drop (`planDrop`) and runs a single `state.js` call.

Drop targets and results:
| Dragged | Dropped on | Result |
|---|---|---|
| block type | empty dot grid | if `canvas`: new canvas. Otherwise: new canvas containing that block |
| block type | a canvas / group | adds the block to it (at the drop position in the flow) |
| preset | empty dot grid | new canvas from the preset structure (placeholders) |
| vector | a canvas | adds a vector block with that vector |
| vector | a vector block | swaps its vector |
| font | a text block | sets that text role's font **on the canvas** (so all blocks of that role update) |
| color | a canvas background area | sets the canvas `background` role |
| color | a block / vector layer | sets the role that block/layer uses on the canvas |
| color | a role row in the editor | sets that role |
| anything | a row in the layers tree | same as dropping on that node in the preview |

Additions beyond the table: a `canvas` block dropped on a canvas adds a new canvas after it; a preset dropped on any canvas also makes a new canvas; a vector dropped on a vector block only swaps if the types match (svg↔vector, image↔image), otherwise it is added to the container; a font can be dropped on a `type` row in the editor; a color dropped on a text block also clears its color override, and on a vector the layer under the pointer decides which role changes (`dropColor()`); a color dropped on any other block sets the canvas background. Layer-row drops: `node` rows reorder/move, `block`/`vector` on a leaf row insert after it. The outline is the hovered valid target only (`.drop-target`, or `drop-into/before/after` on tree rows). Dropping files from Explorer onto the window is ignored (use `+ import`).

Show a lime dashed outline on valid drop targets while dragging. Every drop is one undo step.

## 10. Export

- Exports **all visible canvases** as laid out in the auto grid (at 100% zoom, ignoring current pan/zoom), with their `OPTION` labels.
- Rendered with **html-to-image** from an offscreen export container at `pixelRatio = scale`.
- **PNG** with transparent toggle on: the dot grid and app background are excluded; canvases keep their own backgrounds. **JPEG**: always on a solid background.
- **Style labels** checked: append a strip below the canvases listing, for everything used: each color as a swatch with name + hex; each font written **in its own typeface** with family + weight; each vector's name next to a **one-color black version** of it.
- After rendering, `window.api.saveExport()` opens a save dialog with a default name like `stylesheet_export_2026-10-07.png`.
- Imported fonts must be embedded in the export (make sure html-to-image can fetch them through `ssfile://`).

**As built:** the offscreen sheet is built into `#export-root` by `export.js` using the same `renderCanvasElement()` as the preview (no selection outline, no shadow). The sheet has 24px padding; background is white for JPEG or when transparent is off, transparent otherwise (the style-labels strip is always a white card). `html-to-image` is called with `pixelRatio: scale` and a hand-built `fontEmbedCSS` (every used library font fetched through `ssfile://` and inlined as a data URI, plus bundled IBM Plex Mono via `window.api.readBundledFont`), because a `file://` page cannot `fetch()` its own font files. The strip lists each unique role color (library name if the hex matches a library color/swatch, else the role names), each used font as `Family weight` in its own typeface, and each used vector as a black one-color version (rasters use `filter: brightness(0)`). `transparent` stays stored while JPEG is selected; the toggle just shows disabled/off.

## 12. Gotchas to remember
- Frameless window: buttons inside the drag region must be `-webkit-app-region: no-drag` or they won't click.
- Illustrator often puts fills on paths or in a `<style>` block with classes. To recolor a named layer, strip `fill` attributes/class fills from its descendants on import and apply the fill on the group instead (keep `fill="none"` paths as none).
- Register imported fonts with the `FontFace` API using `ssfile://` URLs, and wait for `document.fonts.ready` before export.
- `position: sticky` breaks inside `overflow: hidden` ancestors — use flex layouts for panel headers.
- Decorative pseudo-elements need `pointer-events: none`.
- Save on quit: block the quit until the renderer confirms the session flush (with a short timeout fallback).
- Drop handlers must run the planned action **before** clearing the drag payload (the planned closures read the dragged id lazily).
- Restoring from trash: wait for the main-process trash sync (`whenTrashSynced()`) before reloading the file, or the read races the file move.
- Font table offsets differ by format: in a TTF/OTF directory entry the offset is at +8, in WOFF at +4.
- `html-to-image` copies the root's computed styles, so the offscreen export node must be `position: static` inside an off-screen wrapper (not itself positioned off-screen).
- A `file://` page can't `fetch()` local files; use `ssfile://` (library files) or a `window.api` call (bundled fonts).

## 13. Decisions made where the spec was silent (assumptions log)

Add to this list whenever a new assumption is made.
- Canvas fonts store library font **ids** (not family names) because the picker chooses weight/style too. Default weight = closest to 400.
- Canvases have an `aspect` field (default 8/9); the grid cell size is fixed at 384px wide at 100% zoom.
- Text blocks with no resolvable font, or with empty text, render the gray placeholder (type name). Preset blocks start with empty text.
- Choosing a role on a text block, or dropping a color on it, clears that block's color override so the change is visible.
- Library deletes: colors/palettes/presets are never "in use" (they hold copies). Deleting a font deletes the whole family. Palette-swatch deletes are trashed as `palette_color` and can only be restored if their palette still exists.
- Undo history includes the library (so deletes undo). Importing a file can be undone, but the copied file stays on disk (harmless; redo reuses it).
- "Clear canvas" = remove all canvases and leave one empty `lockup_A`.
- "Default export scale" in settings is `session.export.scale` (one value shared with the export bar).
- Canvas names auto-increment to the first free letter (`lockup_A` … `lockup_Z`).
- The grid re-fits when the visible canvas count changes; `fit` caps at 100%.
- Layout shown in the editor for a selected leaf block is its parent container's (group or canvas).
- Color/palette names are slugged to `lowercase_with_underscores` when edited.
- Default `symmetrical_logo` etc. structures and the `business_card` / `social_post` structures are my own designs.
- Vector library tiles show a lime border when any block uses that vector.

## 14. Dev and testing notes

- `npm start` runs the app; `npm run dist` builds `dist/Stylesheet_-Setup-<version>.exe` (NSIS, unsigned, so SmartScreen warns). Packaged-app smoke test: `dist/win-unpacked/Stylesheet_.exe`.
- If Electron launches as plain Node ("Cannot read properties of undefined (reading 'setPath')"), the shell has `ELECTRON_RUN_AS_NODE` set; unset it.
- **Dev-only environment variables** (honored only when the app is not packaged, except `STYLESHEET_USERDATA`): `STYLESHEET_USERDATA` (use a throwaway data folder; keep the path short, long paths break Chromium's cache), `STYLESHEET_DEBUG=1` (print renderer console messages to the terminal), `STYLESHEET_HARNESS=<file.js>` (a test harness that receives `{app, win, ipcMain}`), `STYLESHEET_IMPORT=<path;path>` (skip the import dialog), `STYLESHEET_EXPORT_PATH=<file>` (skip the save dialog). Test harness scripts are kept outside the repo.
- Automated checks done so far were scripted launches (screenshots, simulated drag events, close/reopen, export, trash flows). Real mouse/keyboard dragging, native file dialogs and the installer itself have not been exercised by hand.
