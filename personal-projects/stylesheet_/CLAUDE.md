## 1. What this app is

**Stylesheet_** (displayed exactly like that, with the trailing underscore) is a Windows desktop app made by HALFWIT Studios. It is a fast brand sketchbook that sits next to Figma and Illustrator. It does not replace them.

The user imports finished vectors (SVGs from Illustrator), fonts, and colors, arranges them into simple block-based layouts, duplicates those layouts into side-by-side variations with different palettes or fonts, and exports flat PNG/JPEG/WebP reference images to send to clients or to color-pick from in Figma/Illustrator.

Core use case (a client logo job):
1. Designer builds a logo mark in Illustrator (any SVG works; no layer naming is needed). The wordmark is NOT baked into the SVG.
2. Imports the SVG into Stylesheet_. Drops it on the empty preview (a board that sizes itself to its content), then adds a heading block (wordmark) and a body block (tagline).
3. Duplicates the board ~5 times, gives each a different set of colors. Exports with style labels (each board is labeled with its name, `Board 1`, `Board 2`…, or whatever it was renamed to). Client replies "Board 3".
4. Locks in Board 3's colors on every board, swaps the heading font on each instead. Exports again. Client picks.
5. Builds the final, exports large (4×) as a reference for the real brand work elsewhere.

It will be offered as a **free download** on the HALFWIT Studios website, so it must work for people other than the author.

## 5. Architecture rules

### 5.1 Single source of truth
All app data lives in **one state object** in `state.js`. Nothing else holds its own copy.

- Modules **read** state and **render** from it.
- Modules **change** state only through functions exported by `state.js` (e.g. `addBlock()`, `updateBlock()`, `selectNode()`), which then notify subscribers.
- After any change, every panel that depends on it re-renders. Simple full re-renders of a panel are fine — performance is not a concern at this scale. Clarity is.
- The preview and the layers tree are two views of the same data. Dragging onto the preview and editing in the editor both call the same state functions. **They can never disagree.**

### 5.2 Undo
`state.js` keeps a history stack of state snapshots (max 50). A snapshot is a deep copy of **the canvases, the selection (the whole list of selected ids; restored through the same selection rules, so ids that no longer exist drop out), and the whole library (including the trash list)**. Multi-item actions (delete, duplicate, paste, `+ block` on several canvases) are ONE history entry; the copy/paste clipboard is in memory only and is not part of history, so deleting a library item is undoable. Zoom/pan, export settings and UI collapse state are NOT part of history. `Ctrl+Z` undoes, `Ctrl+Shift+Z` / `Ctrl+Y` redoes (ignored while typing in an input). Slider drags and text typing push one history entry per gesture (the first tick), and the next gesture starts a new one (`endGesture()` on the input's `change` event). Because undo/redo replace `state.library` and `state.session.canvases` wholesale, modules must never cache those objects.

Subscribers receive a `meta` object: `{ library, session, live, view, selection, ui, exportSettings, history, refresh }`. Panels skip re-rendering for irrelevant flags (e.g. `view` only updates the zoom transform; `live` slider ticks don't rebuild the properties panel). `requestRender()` redraws everything without changing data (used after fonts/media finish loading). "Empty trash" is not undoable and clears the history.

### 5.3 Electron security
- `contextIsolation: true`, `nodeIntegration: false`, `sandbox: true`.
- The renderer never touches Node or `fs` directly. Everything goes through `window.api` defined in `preload.js` using `contextBridge` + `ipcRenderer.invoke`.
- Imported files are served to the renderer through a custom protocol **`ssfile://`** registered in `main.js` (privileged, `supportFetchAPI: true`, `standard: true`, `secure: true`, plus `corsEnabled: true` so `fetch()` from the `file://` page can read imported files) that maps only into the app's library folder. Reject any path that resolves outside it. URL form: `ssfile://lib/fonts/<fileName>` and `ssfile://lib/media/<fileName>` (the host is always `lib`; responses carry `access-control-allow-origin: *`).
- `index.html` has a Content-Security-Policy meta tag: only the app's own files and `ssfile:` (scripts: self only).

### 5.4 window.api (preload)
```
window.api = {
  loadLibrary(), saveLibrary(data),
  loadSession(), saveSession(data),
  loadSettings(), saveSettings(data), // userData/settings.json: { launch: 'maximized' | 'windowed', lastFolders: { fonts, media, export } } (default maximized, no folders); read by main before the window is created. saveSettings only takes `launch`; lastFolders is written by main itself
  importFiles(type),           // type 'font' | 'media': opens a file dialog limited to that type (starting in that type's last import folder), copies chosen files into the library folder, returns metadata
  readLibraryFile(relPath),    // returns text (used for SVG contents)
  saveExport(dataUrl, format), // format 'png' | 'jpeg' | 'webp': opens save dialog (starting in the last export folder), writes the image
  openLibraryFolder(),
  window: { minimize(), toggleMaximize(), close(), isMaximized(), onMaximizeChange(cb) },
  onBeforeQuit(cb)             // lets the renderer flush the autosave before the app closes (cb may return a promise)

  // Added beyond the original spec:
  syncTrash(files),            // files = [{subdir, fileName}] that SHOULD be in library/trash; main moves files so disk matches (also moves unlisted trash files back = restore/undo)
  purgeTrashFiles(files),      // permanently deletes those files from library/trash (empty trash)
  readBundledFont(name),       // base64 of a bundled UI font in src/fonts (whitelisted ttf names) so exports can embed IBM Plex Mono and Space Grotesk
  getVersion(),                // app version from package.json
  samplePixel(x, y),           // eyedropper: "#RRGGBB" of the window pixel at (x, y) in CSS px (webContents.capturePage of a 1×1 rect), or null
  installDefaultMedia()        // first launch only: copies src/defaults/media/* (logo, then wordmark) into library/media; returns importFiles()-style metadata
}
```
`importFiles()` returns `[{kind:'font'|'media', subdir, fileName, originalName, ext}]`; stored file names are `<timestamp><rand>_<original name>` so two files with the same name never collide.

## 6. Persistence (no projects, no file names)

There are **no projects, no Save As, no file names.** The app holds one working session.

App data lives in Electron's `app.getPath('userData')`:
```
userData/
├─ library.json        # fonts, colors, palettes, media, presets (+ dataVersion)
├─ session.json        # canvases, selection, zoom/pan, export settings (+ dataVersion)
├─ settings.json       # app settings read by main BEFORE the window exists: { launch: 'maximized' | 'windowed', lastFolders: { fonts, media, export } }
├─ library/
│  ├─ fonts/           # copied font files
│  ├─ media/           # copied SVGs and raster images
│  └─ trash/           # soft-deleted files (trash/fonts/, trash/media/); the list of trashed items lives in library.json
└─ old-data-backup-<YYYY-MM-DD>/   # only created for data from v1.1.0 or older (no dataVersion); never for current data
```

- **Data version + fresh-start wipe (`main.js`):** library.json and session.json both carry `dataVersion` (currently **2**, `DATA_VERSION` in `main.js`). Main adds it on every save and strips it on load, so the renderer never sees it. At startup, before the window exists, `backupOldData()` checks both files: if either one exists but has no `dataVersion`, an older one, or can't be parsed, main moves `library.json`, `session.json` (plus any leftover `.tmp` files) and the whole `library/` folder (fonts, media, trash) into a new `userData/old-data-backup-<local date>/` (`-2`, `-3`… if that name is taken). Then both files are missing, so the app starts **exactly like a first launch** (first-run defaults, default media, help overlay). `settings.json` is never moved (launch setting and last folders are kept). Current-version files are never touched; a newer version is left alone too. If the move fails, main shows an error box and quits without loading or deleting anything. **There is no upgrade code for old saves any more.**
- **One copy of Robert's data (Robert's rule): do NOT bump `DATA_VERSION` and do NOT write upgrade code.** Robert keeps exactly one copy of his app data (`%APPDATA%\Stylesheet_`), no backups or versions. **At the end of EVERY change/batch, ask Robert whether he wants that folder deleted** (only delete on a yes, after looking at it), so he can open the app like a brand-new user. Throwaway test folders (`STYLESHEET_USERDATA` in TEMP) are deleted when testing is done. His data never ships: the installer only packs `main.js`, `preload.js`, `src/**/*` and `package.json`. `DATA_VERSION` stays at 2 forever, so current data is never backed up or versioned: it simply updates in place as Robert works. The backup logic above only still matters for someone updating from the public v1.1.0 release (their data has no `dataVersion`).
- **Where data lives vs. what ships:** everything a user imports or makes (fonts, SVGs, colors, palettes, presets, boards) lives only in their own `%APPDATA%\Stylesheet_`. The installer (`npm run dist`) packs only `main.js`, `preload.js`, `src/**/*` and `package.json` (the `files` list in `package.json`), so a new user always starts with exactly the shipped defaults (section 7 "First launch": starter colors, palettes, the logo and wordmark in `src/defaults/media/`) and never with Robert's assets. Nothing needs deleting before a build.
- **History (2026-10-14):** the spacing pass changed `padding` from a number to per-side values without a version bump. Robert's data folder (including the `old-data-backup-2026-10-14` folder the boards pass had created) was deleted once at the end of that pass, so no backup copies remain. Robert reopened the app the same evening (a fresh folder with only the defaults; that is his one copy), and the three throwaway test folders in TEMP (`ss_wipe`, `ss_t16`, `ss_spacing`) were deleted. `%LOCALAPPDATA%\stylesheet-updater` only holds electron-builder's cached installer, not app data.
- **Importing copies files in.** The user's originals can be moved or deleted without breaking anything.
- **Autosave:** session saves 1 second after the last change (debounced), and always on close (the window's `close` event is held until the renderer flushes both files, with a 2-second timeout fallback). Library saves immediately on change.
- **Soft delete (trash):** every library delete (right-click → delete, always behind a confirm dialog) moves the item into `library.trash` and, for fonts and media, moves its file into `library/trash/`. Nothing is permanently removed until the user chooses "empty trash" in Settings. Undo (Ctrl+Z) or "restore" in Settings puts it back. `persistence.js` keeps the folder in sync with the list after every library change (and on startup, to self-heal), and the app waits for that sync before reloading restored files.
- **settings.json** holds app-level settings: `launch` and `lastFolders`. It is separate from session.json because `main.js` needs it before creating the window. A missing/invalid file means `maximized` and no remembered folders. Changing `launch` never resizes the current window; it applies on the next launch. `main.js` keeps the one live copy in memory (`getSettings()`), so the renderer's `launch` saves and the folder updates never overwrite each other; `cleanSettings()` sanitizes every load and save (only absolute path strings survive in `lastFolders`).
- **Dialog folder memory (`lastFolders`):** the fonts `+ import` dialog, the media `+ import` dialog and the export save dialog each remember their OWN last folder (`fonts`, `media`, `export`). After an import that copied at least one file, the folder the files came from is stored; after a successful export, the folder it was saved to. A cancelled dialog changes nothing. The next time that dialog opens it starts there (export: that folder + the usual default file name). If the stored folder no longer exists, the dialog falls back to the old default (Windows' default for imports, Pictures for export).
- Write JSON atomically (write to a `.tmp` file, then rename) so a crash never corrupts data (settings.json too).
- **Never bundle user fonts in the installer.** The installer ships no user data. It does ship the default media files (`src/defaults/media/`, included by electron-builder's `src/**/*`); on first launch (no library.json and no session.json, which includes the launch right after a fresh-start wipe) `app.js` asks main to copy them into `library/media/` and adds them to the library (not an undo step). Existing libraries never get them added.

## 7. Data model

On disk both objects also carry `dataVersion: 2` (written by main, see section 6); it is never part of the state.

```js
library = {
  fonts:    [{ id, family, fileName, style, weight }],   // one entry per font FILE; UI groups by family. style: 'normal'|'italic'; weight: number (e.g. 700)
  colors:   [{ id, name, hex }],                          // name is lowercase_with_underscores by default
  palettes: [{ id, name, colors: [{ id, name, hex }] }],  // any number of colors
  media:    [{ id, name, fileName, kind: 'svg'|'image', addedAt }],   // name = original file name (e.g. mark.svg); addedAt = Date.now() at import (newest-first sorting). An SVG's layers are NOT stored: svg.js reads them from the file every time it is loaded (layerInfo(mediaId))
  presets:  [{ id, name, addedAt, structure: <canvas without any assigned fonts/colors/media> }],   // addedAt = Date.now() when saved (newest-first sorting); new installs start with []
  trash:    [{ id, kind: 'font'|'color'|'palette'|'media'|'preset'|'palette_color', item, deletedAt }]
            // soft-deleted items; `item` is the original entry (palette_color: {paletteId, index, color})
}

session = {
  canvases: [canvas, ...],
  selection: [nodeId, ...],              // LIST of selected node ids (empty = nothing). Always one of: blocks that all live in ONE canvas, or canvases (see "Selection rules" in 8.7).
  zoom: 1, pan: { x: 0, y: 0 },          // pan is an offset from where the grid sits at rest (24px in, 100px down)
  export: { styleLabels: true, canvasLabels: true, format: 'png'|'jpeg'|'webp', transparent: false, scale: 1 },   // new-session defaults shown; canvasLabels = the "board labels" checkbox (show each board's name above it)
  collapsedGroups: { colors: true, ... }, // editor property groups the user collapsed, keyed by group name (colors, appearance, text, transform, size, spacing, layout)
  collapsedNodes: { <nodeId>: true },     // layers-tree nodes the user collapsed
  expandedSection: null,                  // the library section filling the whole panel: null | 'blocks' | 'media' | 'fonts' | 'colors' | 'palettes' (setExpandedSection(); not undo)
  helpSeen: false                         // false until the help overlay has been shown once
}

canvas = {                                                   // shown to the user as a "board"
  id, type: 'canvas', name: 'Board 1',                       // new canvases are "Board N" (first free number); the name is the label above it
  background: '#EDEDEE',                                     // hex; every new canvas is #EDEDEE (DEFAULT_BACKGROUND in blocks.js, set by createCanvas())
  bgImage: null | { mediaId, fit: 'cover'|'contain' },       // background image (see "Background images" below); mediaId null = gray placeholder slot
  layout: { direction: 'stack'|'row', gap: 24, align: 'center' },
  size: { mode: 'fixed'|'dynamic', width: 160, height: 160 },   // px at 100% zoom. fixed = exactly width × height (overflow clipped);
                                                             // dynamic = shrink-wraps its content + padding (width/height are then unused)
  padding: { top: 24, right: 24, bottom: 24, left: 24 },     // px between the content and the canvas edge, per side (0–200 each)
  paddingLinked: true,                                       // true = one "padding" slider sets all four sides; false = four sliders
  radius: 8,                                                 // corner radius in px (0–120, DEFAULT_RADIUS 8 = the rounding canvases always had)
  hidden: false,
  children: [block, ...]
}

block = {
  id, type, name, hidden: false,
  opacity: 100,                                              // EVERY block (not boards): 0–100 %, CSS opacity on the block, so it fades the whole block incl. children
  // EVERY block (text, vector, image, group, palette) has spacing; canvases don't have margin or offset:
  margin: { top: 0, right: 0, bottom: 0, left: 0 },          // px OUTSIDE the block (0–200 each): real layout space, pushes neighbours away in the stack/row
  marginLinked: true,                                        // true = one "margin" slider for all four sides; false = four sliders
  offset: { x: 0, y: 0 },                                    // px (−200–200 each): a CSS translate, so it only moves the block visually (neighbours don't move, a dynamic canvas keeps its size)
  // CONTENT blocks (text, vector, image, palette; not groups) also have a transform (hasTransform() in blocks.js):
  rotation: 0, mirrorX: false, mirrorY: false,               // degrees (−180–180, around the block's center); mirror = flip left↔right / top↔bottom. Visual only, like the offset
  // text blocks (heading, body; title, subheading and caption are still valid types but are no longer offered):
  text: 'NORTHFIELD', size: 32, color: '#000000',            // color: this block's own text color (new text is black). New text starts as its type name ("title", "heading"...). text may contain "\n" line breaks
  tracking: 0,                                               // thousandths of an em (like Illustrator), −200–1000 -> CSS letter-spacing
  lineHeight: 1.2,                                           // multiplier, 0.8–3.0
  textAlign: 'left' | 'center' | 'right',                    // the lines INSIDE the block (default left; the block itself is placed by its container's align)
  textCase: 'none' | 'upper' | 'lower' | 'title',            // display only (CSS text-transform; title = capitalize each word); the stored text keeps what was typed
  underline: false,
  wrap: 'fit' | 'fixed', wrapWidth: 320,                     // fit = one line per line break, never wraps; fixed = wraps inside wrapWidth px (40–1600)
  font: 'builtin_spacegrotesk_700',                           // THIS block's own font: a library font id (family + weight + style) or a built-in id (builtin_spacegrotesk_400/500/700, builtin_plexmono_400/500/700). There are no canvas-wide font settings.
  // vector block:
  mediaId, width: 120, layerColors: { "0": '#D9FF43' },       // keyed by FIRST-LEVEL LAYER INDEX (0, 1, 2…); a layer with no entry keeps the original colors from the file
  // image block: mediaId (kind 'image'), width, fill: false. Raster images have no colors.
  //   fill: true = covers its parent (group or board) edge to edge (object-fit: cover), ignoring the parent's padding, clipped to
  //   its radius, drawn BEHIND the parent's other content; width, margin and offset are then unused. Still a normal layer.
  // group block (a nested container; the text blocks inside keep their own fonts). Groups live only inside a canvas and may nest:
  made: 'library' | 'grouping',                               // how it was created (library / + block, or Ctrl+G); a preset uses it to pick the default background
  background: '#D9D9DB' | null,                               // null = transparent ("none")
  bgImage: null | { mediaId, fit },                           // same as a canvas's
  size: { widthMode: 'fixed'|'fit'|'fill', width: 160, heightMode: 'fixed'|'fit'|'fill', height: 160 },   // width/height used only when that axis is fixed (20–1600)
  padding: { top, right, bottom, left }, paddingLinked: true, radius: 8,
  layout: { direction, gap, align }, children: [...]
  // palette block (a bar of equal color sections; NOT a container):
  sections: [{ hex: '#D9FF43', name: 'neon_lime' | null }],   // at least 1. COPIES: a later edit of the library palette never changes them.
                                                              // name = the library color's name when the color came from the library (palette card,
                                                              // dropped/picked library color); null when typed or a default gray
  width: 320, height: 64,                                     // px (width 40–1600, height 20–800)
  orientation: 'horizontal' | 'vertical',                     // sections side by side, or stacked
  radius: 8,                                                  // corner radius (0–120)
  hexLabels: true, names: false,                              // labels drawn in each section: its hex; its (library) name
}
```

**Color format (every color in the app):** a hex string, `#RRGGBB` (fully opaque) or `#RRGGBBAA` (the last two digits are the alpha). Typing 3 or 6 digits anywhere means opaque; 4 or 8 digits keep the alpha, so nobody ever has to type alpha (the alpha sliders write it). An alpha of `FF` is always stored as the short `#RRGGBB` (`normalizeHex()` in `util.js`), so an opaque color looks exactly as before. Helpers in `util.js`: `isHex`, `normalizeHex`, `rgbHex` (drop the alpha), `alphaOf` (0–100 %), `withAlpha(hex, pct)`, `cssColor` (opaque → `#RRGGBB`, with alpha → `rgba(r, g, b, a)`; used for every rendered color: board/group backgrounds, text, vector layer fill/stroke, palette sections), `hexLabel` (`#D9FF43`, or `#D9FF43 · 40%` below 100 %) and `swatchBg` (a swatch/chip background: the flat color, or with alpha the color over a small gray checkerboard). Applies to library colors, palette swatches, board/group backgrounds, text, vector layers and palette block sections. The eyedropper always picks an opaque `#RRGGBB`.

### Palette block
Added from the library's blocks section / `+ block` (`palette`, glyph `▤`, kind `color`; last in `OFFERED_BLOCKS`): **3 neutral grays** (`PALETTE_GRAYS` `#D9D9DB`, `#9A9AA2`, `#5A5A60` in `blocks.js`), 320×64, horizontal, radius 8, hex labels on, names off, named `palette N`. Or by **dragging a whole library palette card** onto a board/group (or a layers row; the empty grid makes a new dynamic board with it): copies of its colors (hex + name), the block named after the palette (`addPaletteBlock()` / `addPaletteToNewCanvas()` in `state.js`). Rendered by `renderPaletteBar()` in `preview.js` (`.block-palette`: flex, `overflow: hidden`, `flex: none`): equal sections (`.palette-section`, `data-section="<index>"`), each with optional labels in small IBM Plex Mono (10px; name above hex, bottom left; dark or light by `contrastColor()` of the section's RGB). Sections: `setSectionColor()` (stores the library name when given, clears it when a hex was typed, keeps it for an alpha slider tick), `addSection()` (gray `#888888`, `SECTION_GRAY`), `removeSection()` (never below 1). It counts as content for a dynamic board.

**Two kinds of new group** (same `group` type, different starting values, `blocks.js`):
- **Library / `+ block` group** (`LIBRARY_GROUP`, `made: 'library'`): background `#D9D9DB` (`GROUP_BACKGROUND`, a bit darker than a board so empty layouts show), width `fill`, height `fixed` 160, padding 16, radius 8, layout stack / center / gap 16, no children. Dropping it adds an EMPTY group.
- **Grouped in the layers tree** (Ctrl+G / right-click → group; `groupingDefaults()` + `groupNodes()` in `state.js`; `made: 'grouping'`): background `null`, width and height `fit`, padding 0, radius 0, and a copy of the parent's layout, so grouping never changes how things look. If a grouped block is itself a group that fills an axis, the new group fills that axis too (otherwise the inner fill would act like fit and shrink).
- **Empty groups are never removed automatically** (the old auto-prune is gone): you can build empty layouts first and fill them later.

There is no swatch block and no spacer block (spacer was removed in the spacing pass: use a block's margin instead).

### Group sizing (fixed / fit / fill)
Each axis of a group has its own mode (`groupSizing()` in `preview.js`, `GROUP_SIZE_LIMITS` 20–1600, `GROUP_EMPTY_MIN` 40 in `blocks.js`):
- **fixed:** exactly `width` / `height` px (along the parent's direction it never shrinks).
- **fit:** shrink-wraps its content plus padding. An empty group (no visible in-flow child) is at least 40×40 on its fit axes (and on fill axes that resolve), so it stays visible and droppable.
- **fill:** along the parent's direction it takes the remaining space (`flex: 1 1 0`; several fill siblings share it equally); across it, it stretches (`align-self: stretch`).
- **Fill needs a definite parent size on that axis.** A fixed board has both; a dynamic board has neither; a group's axis is definite when it is fixed, or fill inside a definite parent axis; fit is never definite. **Inside a dynamic board or a fit group, fill behaves like fit**, with one exception: an EMPTY group (no visible in-flow child) gets **160px** (`EMPTY_SIZE`) on that unresolvable fill axis instead of the 40px minimum, like a fixed size. A group with content fits its content.
- **Clipping:** a group clips its content (`.clips`, `overflow: hidden`) unless BOTH axes are fit (`groupClips()`), so Ctrl+G groups never clip.
- A group's content is centered along its flow, like a board's (only visible when the group is bigger than its content).
- Switching an axis to fixed stores the group's current rendered size (measured, unclamped), like a board going dynamic → fixed.

### Background images (boards and groups)
`bgImage = { mediaId, fit }` draws the media item (an image or SVG, as the file is: SVGs keep their original colors) above the background color and below the content, covering the whole board/group (padding included), clipped to its radius. `fit` = `cover` (default) or `contain` (centered). A `bgImage` whose media is missing (a preset slot, or a deleted item) draws a gray placeholder. Set only from the properties (appearance group); dropping media on a board/group in the preview still adds a block.

**Paint order inside a board or group** (`backgroundLayer()` in `preview.js`): background color (on the element) → one `.bg-layer` (absolute, inset 0, `z-index: -1`, `border-radius: inherit`, `overflow: hidden`, `pointer-events: none`) holding the background image and then any fill images in layer order → the normal content. Boards and groups are `isolation: isolate`, so `-1` means "above my own background, below my content". Fill images take the pointer back (they are clickable layers); the background image doesn't (a click on it selects the board/group).

### Spacing: padding, margin, offsets
Constants and helpers live in `blocks.js` (`PADDING_LIMITS` 0–200, `MARGIN_LIMITS` 0–200, `OFFSET_LIMITS` −200–200, `SIDES`, `sides(n)` = the same value on all four sides, `sidesCss()` = the CSS shorthand). `renderCanvasElement()` / `renderBlock()` in `preview.js` apply them, so the preview and the export render them identically:
- **Padding** (canvases only): the canvas content's CSS `padding`, per side.
- **Margin** (every block): the block element's CSS `margin`, per side. It is real flex layout space, so it pushes neighbours away within the stack/row (and adds to a dynamic canvas's size).
- **Offset x / y** (every block): `transform: translate(x, y)` on the block. Purely visual: neighbours don't move and a dynamic canvas does NOT grow (content pushed past a fixed or dynamic canvas edge is clipped by its `overflow: hidden`).
- **Rotation / mirror** (content blocks): added to the SAME transform after the offset (`blockTransform()` in `blocks.js`: `translate(x, y) rotate(r) scale(±1, ±1)`, around the block's center), so it is just as visual: the layout around the block never changes. Preview and export both apply it in `renderBlock()`. A fill image ignores it (it covers its parent).
- **Linked / unlinked** (`paddingLinked`, `marginLinked`, saved per item): linked shows one slider that writes all four sides; unlinked shows four. Switching back to linked sets all four sides to the top value.
### Board names
Every new canvas is named `Board N`, the **first number no canvas uses yet** (`nextCanvasName()` in `state.js`, `BASE_NAME` 'Board' in `blocks.js`): the board block (drop or `+ block`), `+ add board`, a block/media/preset dropped on the empty grid, duplicates (Ctrl+D), pastes and `clear boards`' fresh `Board 1`. A renamed board frees its number, so a later new board can fill the gap. The name is exactly what the label above the board shows (8.6) and what the export's style-labels strip uses as that board's heading (section 10). Every canvas is created by `createCanvas()`, so every new board starts #EDEDEE, radius 8.

### Canvas size (fixed / dynamic), padding and corner radius
Constants live in `blocks.js` (`EMPTY_SIZE` 160, `DEFAULT_PADDING` 24, `SIZE_LIMITS` 100–1600, `PADDING_LIMITS` 0–200, `DEFAULT_RADIUS` 8, `RADIUS_LIMITS` 0–120).
- **Corner radius (`canvas.radius`):** rounds the board's corners in the preview and the export (set inline by `renderCanvasElement()`; `overflow: hidden` clips the content to it, so with a transparent PNG/WebP export the area outside the corners is transparent). The background-drop outline (`.pick-bg`) follows it. Presets store it.
- **Empty new canvases start fixed 160×160, padding 24 on every side (linked):** the board block (drop or `+ block`), the `+ add board` button, and `clear boards`' fresh `Board 1` (`createCanvas()`). (A first launch has no board at all.)
- **Canvases created with content start dynamic, padding 24:** a block or media item dropped on the empty grid (`addBlockToNewCanvas()` / `addMediaToNewCanvas()`), `+ block` with nothing selected, and a preset whose structure is dynamic.
- **A dynamic canvas requires content** (any visible block in the flow: `hasVisibleContent()` in `blocks.js`. A visible group counts even when empty, since it is at least 40×40; a fill image does NOT count, since it covers its parent instead of giving it a size, so a dynamic board whose only layer is a fill image switches to fixed 160×160). With none, `dynamic` is disabled in the properties. If a dynamic canvas loses its last visible block (deleted, hidden, dragged out…), `fixEmptyDynamicCanvases()` in `state.js` (run at the end of every `change()`) switches it to fixed 160×160 inside the same undo step.
- **Switching dynamic → fixed** stores the canvas's current rendered size at 100% zoom (measured from the preview, rounded, not clamped to the slider range) so nothing jumps; fixed → dynamic only changes the mode.
- Duplicates, copy/paste and presets keep the size settings, radius, padding, margins, offsets and linked states (they are deep copies / structure).

### Colors: every colorable thing stores its own (no roles)
There are **no color roles**. A color belongs to exactly one thing and a change to it never touches any other block:
- the **canvas background** (`canvas.background`),
- each **group's background** (`group.background`, or `null` = transparent),
- each **text block's color** (`block.color`),
- each **first-level layer of a vector block** (`block.layerColors[index]`),
- each **section of a palette block** (`block.sections[index].hex`).

Every one of them may carry an alpha (see "Color format" above).

A **first-level layer** is a direct child of the SVG root (a group or a shape; `<defs>`, `<style>`, `<title>` etc. are not layers). If the root holds exactly one group that itself holds several drawable children (Illustrator's usual wrapper), the wrapper is skipped and its children are the layers. **No layer naming is required: every SVG works.** A layer's display name is Illustrator's real name when it has one (`data-name`, or a non-generic `id`), else `layer 1, 2, 3…`.

A vector shows **the colors that are actually in the file**. A layer keeps its original colors (even several inside it) until the user gives it a color; then the whole layer becomes that one color. Removing the entry (`reset` in the colors section) returns the layer to its original colors. Library colors are copied in as plain hexes (a later edit of the library color does not change blocks).

### Fonts: every text block has its own font
There are no canvas-wide font settings and no font roles. Each text block stores its own `font`, so two titles in one canvas can use different fonts, and copies/duplicates/pastes keep the font of the block they came from.
- **Built-in fonts:** **Space Grotesk** (the default) and IBM Plex Mono, each at 400, 500 and 700, are the UI fonts that ship in `src/fonts` (`BUILTIN_FONTS` / `DEFAULT_FONT_ID` in `fonts.js`, ids `builtin_spacegrotesk_<weight>` / `builtin_plexmono_<weight>`, `builtin: true`). They are NOT in `library.fonts`, can't be deleted, appear as (undeletable) cards in the library's fonts section (since the first-run defaults pass; see 8.5), but are listed in every font picker (`allFonts()` in `state.js` = built-in + library). Every new text block (from `+ block`, a drop, or a preset) starts in Space Grotesk 700 (Bold), so text is never a placeholder waiting for a font.
- A block whose font was deleted from the library shows the properties font button as `missing ▾` and renders in the default font, Space Grotesk (it re-links if the font is restored).
- Each library font file is registered under its own CSS family `ssf-<fontId>` and rendered at `font-weight: normal` (the weight lives in the file), so there is never faux bold. Built-in fonts are drawn with the real family and `font-weight` (Space Grotesk is one variable file, so any weight 300–700 works) (`fontCss()` in `fonts.js` returns the right CSS for either kind).
- **Font choice = family + weight/style.** The font picker lists families (including the built-in IBM Plex Mono and Space Grotesk); choosing one (or dropping a family card) assigns the weight **closest to 400** (normal style preferred, a tie goes to the heavier weight). A weight/style selector next to the picker then switches among that family's files. Fonts are shown as `Space Grotesk 700` / `DM Serif Display 400 italic` / `IBM Plex Mono 500`.

### Presets
"Save as preset" (exactly one board selected) stores that board's **structure only: all block-level structure, no content.** `nodeToStructure()` in `blocks.js` starts from a full copy of every block and deletes only the content fields (`CONTENT_FIELDS`: `id`, `text`, `font`, `color`, `background`, `mediaId`, `layerColors`, `sections`), so every structural setting is kept automatically (also any added later):
- **Kept:** block types, order, nesting, names, hidden state, layout, sizing modes and sizes (board size mode/width/height, group size modes + sizes, vector/image width, palette width/height, text wrap width), spacing (padding, margin, offsets, linked states), radius, opacity, rotation/mirror, text size / tracking / line height / alignment / case / underline / wrap, a palette's section COUNT (`sectionCount`), orientation and label toggles, image `fill`, a group's `made`, a background image's `fit`.
- **Back to defaults** (`structureToNode()` / `canvasFromStructure()`): every color (boards #EDEDEE, text black; groups by how they were made: **library / `+ block` groups `#D9D9DB`, Ctrl+G groups none** (`made`); any alpha goes with the color), fonts (Space Grotesk 700), text content (the block's type name, as ordinary editable text: `heading`, `body`…), media (vector/image blocks show **gray placeholders**), background images (an empty slot `{ mediaId: null, fit }` = a **gray placeholder**), palette section colors (neutral grays, `PALETTE_GRAYS` repeated, no names).

**The app ships NO default presets** (a new library starts with an empty preset list; "save as preset" still works). Older versions shipped five (`LEGACY_PRESETS`); that list was removed together with the old-save upgrade code, since old libraries are now backed up instead of loaded. Preset-created text blocks start with their type name as text (not empty), in Space Grotesk 700. A board made from a preset is named `Board N` like any new board.

First launch (no library.json and no session.json, including right after a fresh-start wipe, see section 6) starts with (`STARTER_COLORS` / `STARTER_PALETTES` in `blocks.js`, `defaultLibrary()` / `defaultSession()` in `state.js`):
- **blocks offered:** board (`canvas` in code), group, vector, image, heading, body, palette (`OFFERED_BLOCKS`); **no presets**.
- **media:** `Stylesheet_Logo.svg` and `Stylesheet_Wordmark.svg` (from `src/defaults/media/`; the logo has the newer `addedAt`, so it sorts first).
- **fonts:** only the built-in Space Grotesk and IBM Plex Mono (shown as cards, see 8.5); `library.fonts` is empty.
- **colors:** `pure_black` #000000, `pure_white` #FFFFFF, `pure_red` #FF0000 (the `defaults` palette's red), `neon_lime` #D9FF43.
- **palettes:** `defaults` (`white` #FFFFFF, `black` #000000, `red` #FF0000) and `stylesheet_` (five UI token colors, named as colors: `ink_black` #0F0F11 (--panel), `charcoal` #141417 (--card), `graphite` #26262B (--line), `slate_grey` #33333A (--line-2), `lime_green` #D9FF43 (--accent)).
- **no boards:** the preview opens on its empty state (the dashed `+ add board` button, see 8.6); `session.canvases` starts as `[]`. The first board made is `Board 1`.
- **export:** style labels on, board labels on, PNG, transparent off, 1×. **Launch:** maximized (settings.json default).
Existing libraries and sessions are never changed by these defaults.

**Sorting (display only; `sorting.js`; the saved arrays are never reordered, and every edit re-renders so renamed/edited items re-sort):**
- media: newest added first (`addedAt` timestamp set on import).
- fonts: alphabetical by family, case-insensitive (`groupFamilies()` in `fonts.js`).
- colors (by their RGB part; a color's alpha doesn't change where it sorts): pure black `#000000` first, pure white `#FFFFFF` second, then every color with saturation ≥ 10% by hue (red → orange → yellow → green → blue → purple → back toward red; hues are bucketed in 15° steps, shifted so reds on both sides of 0° share a bucket, and lightness dark→light orders colors inside a bucket), then the low-saturation colors (grays, browns; saturation < 10%) last, dark to light.
- palettes: alphabetical by name, case-insensitive. Swatches inside a palette keep the order the user made.
- blocks section: the offered blocks in a fixed order (`OFFERED_BLOCKS` in `blocks.js`, used as `BLOCK_ORDER` / `sortBlockTypes()` in `sorting.js`: `board` (`canvas` in code), `group`, `vector`, `image`, `heading`, `body`, `palette`), then presets newest first (each saved preset has `addedAt`). The editor's `+ block` menu shows exactly the same list in the same order (`sortBlockTypes()`).

Section details (on screen the order is blocks, media, fonts, colors, palettes):
- **media** — `+ import` button in the header (opens a file dialog that only accepts `.svg .png .jpg .jpeg`). Long cards styled exactly like the color cards: a 34px square thumbnail on the left (same size as the color swatch), the file name beside it (truncated with an ellipsis, never wrapped), and a muted line under it with the file type (`svg`, `png`, `jpg`). A card in use by a block gets a lime border. Empty state: "import an svg or image". (The internal data key, folder, drag kind and block field are all `media`; the *block types* named `vector` and `image` keep their names.)
- **fonts** — `+ import` button in the header (file dialog only accepts `.ttf .otf .woff .woff2`). Long cards: `Aa` rendered in that font (20px, centered in a 34px square slot `.font-aa`, the color swatch's size; **it always fits:** `fitFontSample()` in `fonts.js` measures the real glyph outlines with a canvas (`measureText` ink box) and, only when they would spill out of the slot (display fonts with huge built-in metrics), scales them down to fit both ways with 2px to spare and centers them; the slot clips anything left over; fonts that already fit look exactly as before. The font picker's family names (a 30px row, 13px) and the export strip's font lines (17px, a 20.4px line) use the same helper, fitted to their line height. The library redraws once a newly imported font has loaded, since it was measured in a fallback font before), family name, and weight/style count (e.g. `5 weights`; `2 styles` when only styles differ; `1 weight`). Fonts are grouped by family (one card per family; the `Aa` and the drag payload use the weight closest to 400). Right-click deletes the whole family (all its files) after a confirm. **The built-in fonts (Space Grotesk, IBM Plex Mono) are shown as cards too** (`allFonts()`: `3 weights` each), sorted alphabetically with the imported families and draggable like them. They **can't be deleted: right-click shows no menu at all**, and the card's tooltip says "built-in font, can't be deleted". (If an imported family has the same name as a built-in one, they share a card and its delete only removes the imported files.) The fonts count in the header and status bar counts font **families** (= the cards shown, built-in ones included: `groupFamilies(allFonts()).length`), not files, so a new install shows `fonts · 2`, and an imported family adds 1 however many weights it has.
- **colors** — `+ add` button in header, with an **eyedropper tool button** just left of it (see below; it adds a NEW color). Long cards matching the font cards: 34px swatch square on the left, name above, hex below in muted (`#D9FF43`, or `#D9FF43 · 40%` with a small checkerboard behind the swatch when its alpha is below 100%; `hexLabel()` / `swatchBg()`). Click a card to edit name/hex inline (Enter or clicking away saves, Esc cancels; names are slugged to `lowercase_with_underscores`); right-click → delete. In edit mode the hex input accepts 6 digits (opaque) or 8 (with alpha), and an **alpha slider** (`alphaRow()` in `popover.js`, 0–100%) sits under it: moving it rewrites the hex input's alpha digits (and the swatch), typing a hex moves it (6 digits = 100%); nothing is saved until Enter / clicking away (Enter and Esc also work while the slider has the focus). The hex input has an **eyedropper button** next to it (`.edit-eye`, 22px to match the inputs) that changes THIS color's hex (see "Eyedropper" below; a pick is always opaque). A color card can be dragged onto a palette to copy it in (see palettes).
- **palettes** — `+ add` button in header (creates `palette_N` with one gray color and starts renaming), with an **eyedropper tool button** just left of it (creates a NEW palette from the picked color, see below). Each palette is a card: name on top (double-click to rename), then a **6-column grid of 26px square swatches (`aspect-ratio: 1`, smaller than the 34px color-card swatch) that wraps** to new rows for any number of colors, ending in a `+` tile of the same square size that adds a color. Palette swatches behave **exactly like single colors** (draggable, clickable → small name/hex/alpha editor popover, right-click → delete that color; a swatch with alpha shows the checkerboard). The swatch editor popover has an **eyedropper button** next to its hex input (28px to match the popover inputs) that changes THIS swatch's hex, and the same **alpha slider** as the color card under it (it rewrites the hex input; saved with `save` / Enter). **The card itself is draggable as a whole palette** (drag kind `palette`, `data-drag-kind` on `.palette-card`; not while it is being renamed): dropped on a board/group (or a layers row, or the empty grid) it adds a **palette block** with copies of its colors (section 7). Dragging a swatch still drags just that color (the swatch is the nearest draggable element). Right-click the card to delete the palette.
  - **Dropping colors into a palette** (`planPalette()` in `dragdrop.js`; the card carries `data-palette-id`): a library color card, or a swatch of ANOTHER palette, dropped on a palette card is **copied** in (new id, same name + hex; later edits of the original don't change it; duplicates are allowed; `insertPaletteColor()` in `state.js`). A swatch dropped on its OWN palette is **moved** (reorder, no copy; `movePaletteColor()`). While a color is over a card, the card gets the normal `.drop-target` outline and a thin accent **insertion line** (`.palette-insert`, 2px, absolutely positioned inside the grid, `pointer-events: none`) shows where it will land: over a swatch, its left/right half = before/after it; in the gap between two swatches of the same row, the nearest swatch decides; the line sits halfway between the two neighbors (3px outside the swatch at a row's edge). Anywhere else on the card (its name, empty space, the `+` tile, an empty row area) = the end of the palette, and the line shows after the last swatch. Each drop is one undo step; a reorder onto its own spot does nothing (no history entry).
- **blocks** (listed first on screen) — one section (there is no separate presets section), a single column of the same long cards as fonts/colors (same height, padding, border, radius, spacing): a lime icon centered in a 34px square slot (same size as the color swatch) on the left; the name on the right with a muted second line. Default blocks (`board`, `group`, `vector`, `image`, `heading`, `body`, `palette` (glyph `▤`, kind `color`, 3 gray sections; see "Palette block" in section 7); there is **no spacer block** any more (removed in the spacing pass; use margin); the card shows `typeLabel()`, so the `canvas` type reads `board` while its drag payload stays `canvas`; `title`, `subheading` and `caption` are **no longer offered** anywhere but stay valid types in `BLOCK_TYPES`; the **`group` block** (glyph `▢`) adds an EMPTY library group, see "Two kinds of new group" in section 7; groups can also still be made in the layers tree, see 8.7) have a solid border and show their kind on the second line (`kind` in `BLOCK_TYPES`: title/heading/subheading/body/caption = `text`, vector/image = `media`, board and group = `container`, palette = `color`). Presets come after them with a **dashed border**, a lime `▣` icon and the second line `preset`. Presets drag into the preview, right-click → delete (confirm, soft delete to trash), and "save as preset" adds a new one here.

**Eyedroppers (`eyedropper.js`): ONE shared tool, four buttons, only one runs at a time.** The rule: a **SECTION HEADER** eyedropper creates something **NEW** from the picked color; an **EDIT MENU** eyedropper changes the **ONE** thing being edited.
- **The buttons:** colors header (`#btn-eyedropper`) and palettes header (`#btn-eyedropper-palette`), both created by `buildHeaders()` from `data-eyedropper` in `index.html` and wired with `addEyedropperButton()`; the color card's edit mode and the palette swatch editor popover each have one next to the hex input (`.edit-eye`, started with `startEyedropper()`). All are `.icon-toggle`s like the export bar's transparent toggle (24px in headers, 22px in the color card, 28px in the popover), showing `icon('eyedropper')`, and all carry `.eyedropper-btn`: off = normal button, hover = accent icon, on = accent border + accent icon. A header button (and the color card's button) shows "on" **only while it is the one running**; clicking it again switches it off. Starting any eyedropper switches the running one off first.
- **While on**, the cursor is a crosshair over canvases and the selection outlines are hidden (so they can't be picked). Clicking anywhere on a canvas reads **the exact on-screen pixel** under the pointer (`window.api.samplePixel`, main-process `capturePage`), so it works on images, vectors, text and backgrounds alike, and at any zoom. Wheel zoom, the zoom/fit buttons and space/middle-drag panning still work (the clicks of a pick never select or start a drag-select box).
- **It switches off** when: a color is picked; the user clicks negative space in the preview (dot grid or the floating bars' background); `Esc` (consumed, so it doesn't also clear the selection or cancel an edit); any press outside the preview panel (which still does its normal job); its button is clicked again; or another eyedropper is started. Every way except a pick counts as **cancel**.
- **Colors header (new color):** the picked color is added like `+ add` (name `new_color`, the picked hex filled in) and the card opens in edit mode with the name selected: type a name, press Enter.
- **Palettes header (new palette):** creates `palette_N` (same numbering as `+ add`) holding one swatch of the picked color named `new_color` (`addPalette(name, hex)`), then starts renaming the palette like `+ add`. One undo step.
- **Color card edit mode (that color):** pressing the button doesn't move the focus (its `pointerdown`/`mousedown` are prevented) and, while it runs, the inputs' blur is ignored (`pickingColorId`), so starting a pick never saves or cancels the edit; the card stays in edit mode with the button "on". A pick sets that color's hex (`updateColor`, one undo step) and the card is in edit mode again showing the new hex, with the typed (unsaved) name kept (`colorDraft`). Cancel returns to edit mode exactly as it was typed. If it is cancelled because another eyedropper was started, the edit ends unsaved (like Esc).
- **Palette swatch popover (that swatch):** the button closes the popover and starts the tool. A pick sets that swatch's hex (one undo step) and the popover reopens on that swatch showing the new hex (and the typed name), ready to rename. Cancel reopens it with the old typed values. If it is cancelled because another eyedropper was started, the popover stays closed. (It doesn't reopen if the palettes section is hidden by another expanded section.)

**Palette hover:** the palette card is draggable (as a whole palette), so it gets the same hover as the other draggable cards: a `--line-2` border and the grab cursor (`.palette-card[draggable=true]` in `library.css`; not while renaming). Each swatch is draggable too, so on hover it gets an accent border and the grab cursor, plus a small floating tooltip with its name and hex (`hexLabel()`, so `· 40%` with alpha) (one shared `.swatch-tip` element on `<body>`, so the list's overflow can't clip it; it flips below the swatch if there's no room above and hides on leave, drag, click and right-click).

**Shared section header (one pattern for all five sections):** `.lib-head` elements in `index.html` are empty skeletons with `data-label` (and `data-add` / `data-import` = the id of the button to create); `library.js` `buildHeaders()` fills every one with the same structure. Left: `label · count` in one style (`.lib-label`, 13px muted; counts are live; a new install shows `blocks · 7` (offered blocks + presets), `media · 2`, `fonts · 2` (families), `colors · 4`, `palettes · 2`). Right: one `.lib-head-actions` group (6px gaps) holding, in order, the eyedropper (colors and palettes), then a `+ import` button on media and fonts (`data-import`), a `+ add` button on colors and palettes (`data-add`), otherwise the muted `drag in` hint (blocks only), and **last the expand/collapse button on every section**, so the five expand buttons line up in one column at the far right. `+ import` / `+ add` are the same `.plus-btn` (24px tall; look comes from the shared button style, see 8.10). All headers are 28px tall; the label truncates with an ellipsis rather than ever pushing the buttons (the colors header at 280px has 50px to spare; the palettes header, with the same buttons and a label two characters longer, about 34px, about 26px at `palettes · 10`; calculated from the colors measurement, not measured on screen). The lists reserve the scrollbar space always (`scrollbar-gutter: stable`, `--list-pad` 8px + `--scroll-gutter` 6px) and the header's right padding is the same sum, so the right-side hint/button ends exactly at the cards' right edge whether or not a scrollbar shows.

Scrollbars: 6px, thumb `#3A3A41`, transparent track. The thumb stays gray at rest AND on hover; it turns lime **only while it is pressed/dragged** (`::-webkit-scrollbar-thumb:active`, pure CSS in `base.css`, no JS or hover-class logic). Applies to every scroll area (library lists, layers, properties, popovers, settings trash list) and to every `<textarea>` (the properties text box; rules in `base.css`). One-line inputs scroll sideways without a scrollbar, so they need none.

**Deleting library items (any section):** right-click → `delete` → **always a confirm dialog**. If the item is in use, the dialog says how many blocks use it (fonts: text blocks resolving to that font; media: vector/image blocks plus boards/groups using it as their background image; the media card's lime "in use" border counts those too). Confirming moves the item to the trash (see section 6) and shows the notice `moved <name> to trash` (toast + log, see 8.9; `<name>` = file name for media, family for fonts, otherwise the item's name; cancelling shows nothing); blocks that used it fall back to their gray placeholder (and re-link if the item is restored). Deletes are one undo step (Ctrl+Z). Colors, palettes and presets store copies of values, so they are never "in use" and deleting them changes no board.

**SVG import rule:** on import, parse the SVG and sanitize it: remove `<script>`, `<foreignObject>`, event handler attributes, and external references. **No layer naming is needed and no notice is shown:** every SVG works, and it appears with the colors that are in the file. The layers are the first-level layers (see "Colors" in section 7).

Implementation details (`svg.js`): first-level layers are the drawable direct children of the SVG root (`g path rect circle ellipse polygon polyline line text use`); a single wrapper group holding several drawable children is skipped. Generic Illustrator ids (`Layer_1`, `Artboard_2`, `XMLID_3_`, `_x31_`…) don't count as names. Also removed: `<iframe>`, `<object>`, `<embed>`, `<image>`, audio/video, `javascript:` values, and any `href`/`url()` that isn't an in-file `#id`. The original file on disk is never modified: sanitizing and preparing happens **every time an SVG is loaded** (cached in memory per media id, together with `layerInfo(mediaId)` = `[{ name, colors }]`). Preparation: layers get `data-layer="<index>"`; `<style>` rules are scoped per vector (`svg[data-vid="…"] .cls-1`) so classes from different SVGs can't collide (their paint declarations are **kept**, that is the original color); all ids are prefixed per vector; a `viewBox` is guaranteed and fixed width/height removed. **Reading the original colors:** the prepared SVG is mounted off-screen once and `getComputedStyle` gives each painted shape's final fill/stroke (so classes, `<style>` blocks and inheritance are all resolved; gradients use their first stop). Shapes that really have a fill get `data-f`, shapes that really have a stroke get `data-s`, and the distinct colors per layer (drawing order) become `layerInfo().colors`. **Recoloring a layer** (`buildVectorSvg`) sets inline `fill` on that layer's `data-f` shapes and inline `stroke` on its `data-s` shapes, so `fill="none"` shapes stay unfilled and one layer becomes one flat color. Layer display names decode Illustrator's `_x20_` escapes. Raster images (`kind: 'image'`) render as `<img>` and have no colors.

**Font import:** family, weight and style are read from the font's own `name` and `OS/2` tables (TTF, OTF, WOFF; WOFF is inflated with `DecompressionStream`). WOFF2 can't be read in the browser and falls back to guessing from the file name. A variable font imports as one entry at its default weight.

### 8.6 Preview panel (middle)
- Background: `--bg` with a dot grid (`radial-gradient(var(--dot) 1px, transparent 1.2px)`, 18px spacing).
- **Floating top bar** (rounded 10px, `--line` border, semi-opaque `--panel`, soft shadow, inset ~24px from the panel edges): `02 — PREVIEW`, `auto grid · N boards` (`1 board`), and on the right `zoom` with `−` / `100%` / `+` and a `fit` button.
- **Canvases** are laid out in an **auto grid** calculated from the number of visible canvases: 1 → 1 column, 2 → 2×1, 3–4 → 2×2, 5–6 → 3×2, 7–9 → 3×3 (10+: `ceil(sqrt(n))` columns). Never set manually. **Canvases can be different sizes** (fixed width × height, or dynamic = content + padding; see "Canvas size" in section 7). Each grid column is as wide as its widest canvas and each row as tall as its tallest, with every canvas centered in its cell and a 20px gap. This is plain CSS grid (`auto` tracks, `place-items: center`, `width: max-content` so the window width never squeezes dynamic canvases), set by `applyGridLayout()` in `preview.js`, which the export calls too. `fit`, zoom, pan, drag-select and the dot grid all work from the real rendered sizes (fit measures the grid element). Each board's label is its name (see the next point). When the number of visible canvases changes, the view auto-`fit`s (not on ordinary edits). `fit` never zooms past 100%.
- Each board: a card rounded by its own `radius` (default 8px; see section 7) filled with its `background` color, soft shadow. The label above it shows the **board's name, exactly as typed** (`Board 1`, or whatever it was renamed to; no forced uppercase). It sits **outside the board, just above it, aligned to its left edge** (6px gap; IBM Plex Mono 11px, letter-spacing 2px; `--muted` on the dot grid, `#777` on the export sheet), so it never overlaps content whatever the padding. Renaming a board in the layers tree updates its label in the preview and in exports (both redraw from state). Each grid cell is a `.canvas-cell` (label + card, built by `renderCanvasCell()` in `preview.js`, used by preview and export alike; `renderCanvasElement()` builds only the card). The label is only drawn while the export bar's `board labels` checkbox is on (`session.export.canvasLabels`); turning it off removes the label AND its row, so the boards move up by that much. Every selected canvas gets a 2px lime outline (a canvas is outlined only when it is itself selected, not when one of its blocks is).
- Canvas contents render with flexbox from `layout` (`direction`, `gap`, `align`), inset by `canvas.padding` per side; each block adds its own `margin` and is nudged by its `offset` (see "Spacing" in section 7). A fixed canvas clips content that doesn't fit at its edge (`overflow: hidden`); a dynamic canvas (`.canvas.dynamic`) has no size of its own and shrink-wraps its content.
- **Groups** render like small boards: their own background (none = transparent), radius, padding, flex layout (content centered along the flow), and sizing modes (`groupSizing()`; see "Group sizing" in section 7). Fill images and background images go into the board's/group's `.bg-layer` (see "Background images" in section 7); everything else is in the flow. `renderChildren()` splits the two and passes a sizing context (`{ direction, defW, defH }`) down the tree. The preview and the export both use this code. (The name label is outside the board, above it; see the previous point.)
- **Zoom & pan:** the **mouse wheel zooms around the cursor** anywhere over the preview panel (Ctrl is not needed; Ctrl + wheel / trackpad pinch does the same thing). The point under the cursor stays under the cursor. Steps are multiplicative: `zoom × 1.1^(−deltaY/100)`, so one standard notch (100px) is ×1.1 and small trackpad / hi-res deltas scale down proportionally; `deltaY` is capped at ±300 per event and line/page delta modes are converted to pixels. `+`/`−` buttons step 10% around the center. **Double-click the zoom percent to type a value:** it becomes an inline input (same font/size, shows the current number, selected, digits only, max 3 digits). Enter or clicking away applies it, Esc cancels, empty/invalid cancels, below 25 becomes 25, above 400 becomes 400, and it zooms around the center of the preview. Range 25%–400%. Pan with **space + drag** or **middle-mouse drag**. `fit` resets to fit all canvases. Zoom/pan transform only the canvas grid; the floating bars stay put.
- Clicking a block on a canvas selects it (same as clicking it in the layers tree); clicking a canvas selects the canvas. **Ctrl+click or Shift+click** a block or canvas adds it to the selection, or removes it if it is already in (a modifier-click on empty grid does nothing). **Drag-select:** press and drag anywhere in the preview (not while holding space, which pans) to draw a **dashed accent rectangle** (`.marquee`, 1px, fixed-position, `pointer-events: none`); everything the box touches is selected live while dragging. Same rules as the tree: touching two or more canvases selects just those canvases; inside one canvas it selects the blocks the box touches (a block inside a touched group is covered by the group), or the canvas itself if it touches no block. A drag always replaces the selection (Ctrl/Shift don't add to it). Clicking empty dot grid (no modifier) or pressing `Esc` clears the selection. Every selected block gets a thin dashed lime outline. The dot grid zooms and pans with the canvases.
- **Empty state:** with no visible boards (including every first launch) the preview shows a dashed **`+ add board`** button (`#btn-add-canvas`, the same `.dashed-btn` style as `save as preset`, sized to its text) instead of a message. Clicking it adds one empty board (`addCanvas()`, `Board N`, fixed 160×160, padding 24, radius 8; one undo step, same as dropping the board block). Dropping a block, media item, preset or palette card on the empty grid still works as before (the wrapper ignores pointer events; only the button is clickable).
- **Opacity:** a block whose `opacity` is below 100 gets CSS `opacity` on its element (`applyOpacity()` in `preview.js`; fill images too), so the whole block fades, children included. At 100 nothing is set.
- **Colors with alpha** are drawn with `cssColor()` (`rgba(...)`) everywhere: board and group backgrounds, text, vector layer fill/stroke (`buildVectorSvg()` in `svg.js`) and palette sections. A see-through board shows the dot grid behind it in the preview (and is see-through in a transparent PNG/WebP export).
- **Palette blocks** render as a bar of equal sections (`renderPaletteBar()`; see "Palette block" in section 7): `width` × `height`, horizontal (side by side) or vertical (stacked), clipped to `radius`; each section shows its name (when `names` is on and it has one) above its hex (`hexLabel()`, so `· 40%` with alpha; when `hexLabels` is on) in 10px IBM Plex Mono at the bottom left, dark or light for contrast. A color dropped on a section recolors just that section, with an accent frame inside it (`.pick-section`, see the outline below).
- Empty media slots/missing media render as **gray placeholders** (a gray box for vector/image). Text has no placeholder box: a text block always renders its text in its font (Space Grotesk by default); if its text is cleared it shows the block's type name at 40% opacity (`.is-empty`).
- **Double-click a text block** on a board: it is selected and its text becomes **editable IN PLACE** (`startTextEdit()` / `finishTextEdit()` in `preview.js`): the block's own element gets `contenteditable="plaintext-only"` (class `.editing`: text selection back on, text cursor), a blinking cursor in the accent color (`caret-color`), normal text selection drawn as an accent background with near-black `#0A0A0B` text (`.block-text.editing::selection` in `preview.css`, never the default blue; it can't reach an export, which builds its own DOM), all its text selected to start. Every keystroke updates the block's `text` live (`updateNode(..., { live: true })`) and the properties text box (`data-block`); the whole edit is **ONE undo step** (one live gesture, closed by `endGesture()`). **Enter** or clicking away (blur) commits; **Shift+Enter** inserts a line break (`insertLineBreak`, a `\n`); **Esc** commits and exits. While editing, the app shortcuts ignore the keys (the element's keydown stops propagation, and every global handler skips contenteditable targets, the `?` help key included), a press inside the block never starts a drag-select box and a click inside it only moves the cursor. The preview is not redrawn during the live ticks (that would lose the cursor); it redraws once when the edit ends (`requestRender()`), so clearing all the text shows the faded type name again when not editing. While editing, a cleared block is empty (not the type name) and keeps one line of height.
- **Preset-save ripple (a water droplet):** when `save as preset` succeeds, `playRipple()` in `preview.js` (called from `renderPresetFoot()`) makes the dot grid act like a still pool hit by a droplet at the saved board's center: a short bright accent splash at the center (420ms), then 4 concentric rings that travel outward slowly (380px/s on screen, 200px apart) and die down with distance and time (damped) until the pool is still, about **3 seconds** in all (requestAnimationFrame, 60fps). On a crest the dots grow (up to 3.3× their radius), turn toward the accent `#D9FF43` and bunch together (pushed up to 5px radially toward the crest); in a trough they shrink, darken a little below their normal gray and spread apart. Dots outside the wave stay exactly as normal. **How:** a temporary `<canvas class="ripple-canvas">` (first child of `#stage`, so under the boards; with the glass panels on it is as wide as the dot layer under them) lies exactly over the dot grid. It is opaque, so it hides the real CSS dots under it while it plays, and draws every dot itself at the same 18px × zoom spacing and zoom/pan position (the still grid is drawn once into an offscreen canvas; each frame only the moving dots are erased and redrawn from pre-drawn dot images). When it ends the canvas is removed and the real dots show again. A zoom/pan/resize while it plays redraws the still grid so the dots stay aligned (the droplet stays on the board). `pointer-events: none`, so clicks, drags, wheel zoom and pan keep working; a new save restarts it; skipped when Windows' reduce-motion setting is on (`prefers-reduced-motion: reduce`) and when the board isn't drawn (hidden). All timing, speed, ring count, damping and look values are named constants at the top of `playRipple()`.
- **Transforms:** offset, rotation and mirror are one CSS transform on the block (`blockTransform()`; see "Spacing" in section 7). They never move the blocks around it or resize a dynamic board.
- **Text styling** (`textStyleCss()` in `preview.js`): tracking → `letter-spacing: tracking/1000 em`; line height; `text-align`; case → `text-transform` (title = `capitalize`); underline → `text-decoration`; wrap `fit` → `white-space: pre`, no max width (one line per line break, never wraps; a board clips what sticks out); wrap `fixed` → `white-space: pre-wrap` in `wrapWidth` px (capped at the container's width like other blocks).
- **Floating export bar** at the bottom, same glass style (`.float-bar`: semi-opaque `--panel` + `backdrop-filter: blur`), width and inset as the top bar, but **two rows** tall (10px padding, two 34px rows 8px apart; 98px with the border). It is two columns (`.export-col`, 28px apart), each with two stacked rows:
  - **Column 1 (labels):** the `style labels` checkbox, and under it the `board labels` checkbox (`#opt-canvas-labels`, same style; default on; hides the board-name labels in preview and export).
  - **Sizes:** every segmented toggle button is `--toggle-h` (30px) tall with `--toggle-pad-x` (12px) side padding (tokens in `tokens.css`, used by `.seg button`). The transparency toggle is a `--toggle-h` square and the export button is `--toggle-h` tall with `--toggle-pad-x` padding, so both match the format toggle exactly. The rows stay 34px (the bar is still 98px) and the 30px controls are centered in them; the export button gets `margin-top: (34px − toggle-h) / 2` so it lines up with the format toggle on the first row.
  - **Column 2 (file):** `format` PNG|JPEG|WEBP joined segmented toggle with the **transparent background icon toggle** right of it (checkerboard icon; lime border + lime icon when on, gray when off; disabled and shown off only when JPEG is selected, since JPEG can't be transparent; PNG and WebP can); under it `scale` 1×|2×|4× segmented toggle. The `format` / `scale` captions share one width (`6ch`) so both toggles start on one edge, and they are always shown.
  - The `export` button (format-toggle height, see Sizes) sits at the **top right**, on the first row, of the bar (the bar is `align-items: flex-start`) (the one unique button: normal at rest, solid accent background AND border with dark text on hover/press; see 8.10).
  - **Above the export bar's right edge** floats the notifications group (`#notify`, see 8.9): the log button (right edge = the bar's right edge, bottom 134px = 12px above the bar), with the toasts or the expanded log to its left. `fit` reserves 142px at the bottom (`FIT_RESERVED` in `preview.js`) so canvases never land under the bar. If the bar height changes, change `#notify`'s bottom (overlays.css) and `FIT_RESERVED`.

### 8.7 Editor panel (right)
Header: `03 — EDITOR`.

**Height rule:** the editor is a flex column: `03 — EDITOR` header, `.editor-body`, pinned `save as preset`. The body holds two parts. `.props-part` (divider, a `properties` header that uses the same `.layers-head` class as `layers`, nothing on its right, then `#props`) takes its natural height up to **`max-height: 60%`** of the body; beyond that `#props` scrolls inside itself. `.layers-part` (`layers` header + `#layers` list) takes the rest, so at least 40%, and its list scrolls inside itself. Both headers and `save as preset` are always visible (also with nothing or several items selected); the panel never scrolls. (Measured: at 1280×720 the body is 560px, so properties max 336px; at 2048×1152, 962px and 577px.) 

**Property group ORDER (a fixed rule for this and every future batch).** The groups of one item's section always appear in this order, top to bottom:

**colors → appearance → text → transform → size → spacing → layout**

**Relevance rule:** a group only appears when it applies to that item (e.g. an image has no text group, a board has no transform). Never show an empty or irrelevant group. (`appearance` exists for every item: a board's background image; a group's background image + opacity; every other block's opacity. `transform` exists for content blocks only: text, vector, image (not while fill is on), palette.) The order lives in one place, `itemGroups()` in `properties.js`. Which groups each item gets today:

| item | colors | appearance | text | transform | size | spacing | layout |
|---|---|---|---|---|---|---|---|
| board | background | background image | – | – | fixed/dynamic, radius, width/height | padding | its own |
| group | background (or none) | background image, opacity | – | – | width mode + slider, height mode + slider, radius | padding, margin, offset x/y | its own |
| text block | text color | opacity | text, font + weight, B/I/U + align, size, tracking, line height, case, wrap (+ width) | rotation, mirror | – | margin, offset x/y | its container's |
| vector | one row per layer | opacity | – | rotation, mirror | width | margin, offset x/y | its container's |
| image | – | opacity | – | rotation, mirror (hidden while fill is on) | fill toggle, width (hidden while fill is on) | margin, offset x/y (whole group hidden while fill is on) | its container's |
| palette | one row per section (× each), `+ add section` | opacity | hex labels, names | rotation, mirror | width, height, horizontal/vertical, radius | margin, offset x/y | its container's |

**Property groups:** compact control rows (36px, `--row-h`); each group has a collapsible header with a 15px ▾/▸ chevron (all open by default, collapse state saved in `session.collapsedGroups` under the group's name: `colors`, `appearance`, `text`, `size`, `spacing`, `layout`; the layers tree uses the same 15px chevrons). A label + segmented toggle on one line is a `modeRow()` (`.mode-row` in `editor.css`; its label lines up with the slider labels): group width/height modes, image fill, background image fit, palette `hex labels` / `names`. Slider rows are one line (label, slider, value); slider labels are at least 44px wide and grow for longer words (`margin`, `offset x`), so those tracks start a little further right. Direction and align toggles share one line. At window heights ≤820px the row height drops to 26px and spacing tightens (`@media (max-height: 820px)` in `editor.css`).

**layers** (with `+ block` on the right, which opens a small menu of block types):
- A tree. Canvases at the top level with ▾/▸ carets to expand/collapse. Children indented 20px per level.
- Each row: icon glyph + name, and a muted tag on the right (`board`, `3 layers`, `heading`, `body`…; `typeLabel()`).
- Selected row: `#1A1A1E` background, 1px lime outline, its tag turns lime. Every selected row has this style.
- **Selection rules (multi-select).** Plain click selects one row; **Ctrl+click** toggles a row; **Shift+click** selects the rows on screen between the last plainly/Ctrl-clicked row (the anchor) and this one. `Esc` clears. The selection is either **blocks that all live in one canvas, or canvases, never a mix**: a pick that doesn't fit the current selection (a block from another canvas, a canvas while blocks are selected, a block while canvases are selected, or a Shift-range crossing canvases) **switches the selection to just the newly picked item(s)**. It never turns into canvases, so Delete can't remove whole canvases by accident. A block inside another selected block (a group) is dropped: the outer one wins. These rules live in `cleanSelection()` in `state.js`.
- **Groups.** A group can be added EMPTY from the library or `+ block` (the gray library group, see section 7), or made from layers: select blocks (not canvases), then right-click → `group` (or `Ctrl+G`): the blocks are wrapped in a new group named `group 1`, `group 2`… (renameable like any row). The group sits where the first selected block (top of the tree) was, the blocks keep their tree order, and the group **copies its parent's layout** (direction, gap, align) and starts transparent, fit × fit, padding 0, radius 0, so nothing shifts visually (a grouped fill group passes its fill on, see section 7); it then has its own properties. One layer can be grouped, groups can contain groups, canvases can't be grouped. `ungroup` (right-click when the selection includes a group, or `Ctrl+Shift+G`) replaces each selected group with its children in the same spot; the freed blocks become the selection. A group left **empty** stays (it is no longer removed automatically). Groups drag, reorder and move into other groups/canvases like any row. Both actions are one undo step. Saved presets can contain groups.
- **Right-click a row** opens a menu (same popover menu as library deletes): `copy`, `paste` (only when the clipboard has something), `duplicate`, `group` (blocks only), `ungroup` (when a group is selected), `delete`. If the row is not in the selection it is selected first; if it is, the menu acts on the whole selection. Delete is not confirmed (it is undoable, unlike library deletes).
- Hover shows an **eye icon** to hide/show the block (hidden blocks are dimmed in the tree and not rendered).
- Double-click a name to rename. Drag rows to reorder or move into another canvas/group (top/bottom quarter of a row = before/after, middle of a group row = into it; canvases only reorder among canvases).
- Shortcuts (all act on the **whole selection** as ONE undo step, and are ignored while typing in an input): `Delete` removes it; `Ctrl+D` duplicates it (each copy goes right after its original and becomes the selection; a board copies everything, including all its colors and radius, and takes the first free number, e.g. `Board 3`; a block is named `heading 1 copy`, `heading 1 copy 2`…); `Ctrl+C` copies it; `Ctrl+V` pastes (see below); `Ctrl+G` groups the selected blocks and `Ctrl+Shift+G` ungroups the selected groups; `Esc` clears the selection.
- **Paste:** copied layers go right after the last selected layer, or to the end of each selected canvas (one copy per canvas); copied canvases go right after the last selected canvas (or at the end when nothing is selected) and take the first free number (`Board N`). Pasted layers are named `<name> copy`, `<name> copy 2`… (unique inside the destination canvas). Pasting layers with nothing selected shows a notice. The pasted items become the selection.
- **Block names:** a block added without a name is numbered per canvas: `heading 1`, `heading 2`… (first free number). Vector/image blocks added from a library item keep the file name; a palette block made from a library palette card keeps the palette's name; preset-made blocks keep the preset's names.
- Selecting a node in the preview expands any collapsed ancestors in the tree. The `+ block` menu lists exactly the library's offered blocks in the same order: board, group, vector, image, heading, body, palette (`sortBlockTypes()`, labels from `typeLabel()`). `+ block` adds **one new block to the end of every selected board** (or of the board that owns the selected blocks); the `board` item adds a new top-level board; with nothing selected it creates a new canvas containing the block.

**Properties** (below a divider) — contents depend on what's selected; the groups follow the order and relevance rules above:
- **colors**: shows **only the colors of the currently selected item**, one full-width row each (swatch, name, hex or `original`). Canvas → one row `background`. Group → one row `background` (text `none` when transparent; the picker has a first `none (transparent)` row; `reset` = none; a library color can be dropped on it; hover outlines the group's edge). Text block → one row `text`. Vector block → one row per first-level layer (the layer's name or `layer 1, 2, 3…`; the swatch shows the layer's original color(s), split into stripes when there are several, and the text says `original`; once a color is chosen the swatch and hex show it and a `reset` link returns the layer to its original colors). Palette block → one row per section (its library name, or `section 1, 2…`), each with a `×` link that removes it (not on the last one: at least 1 section), then a `+ add section` link (`.add-section`; adds a gray `#888888` section); hovering a row outlines just that section; a library color dropped on a row recolors it (and stores its name). Image blocks have no colors group. A color with alpha shows `#D9FF43 · 40%` and a checkerboard behind its swatch (`hexLabel()` / `swatchBg()`); opaque colors look exactly as before.
- **Color picker** (`openColorPicker()` in `popover.js`): library colors and palette swatches (checkerboard chips for colors with alpha), a hex input (6 digits = opaque, 8 digits keep the alpha) with `apply`, and under it an **`alpha` slider** (0–100%, `alphaRow()`). The slider is **live on the current color**: dragging it changes the selected thing's alpha right away (the hex input follows), the popover stays open, one undo step per drag (the setters take `{ live: true }`; on release `endGesture()` + `requestRender()` redraw the panel). Typing a hex moves the slider to its alpha. Clicking a library color picks it exactly as stored (its own alpha) and passes its name (`onPick(hex, { name })`; a palette section keeps it); an applied typed hex passes `{ name: null }`. With no current color (a transparent group) the slider does nothing.
- **appearance** (every item; collapse key `appearance`; `appearanceBody()`): boards → the background image rows; groups → the background image rows, then `opacity`; every other block → `opacity` only. **Opacity** is a `sliderRow()` 0–100% (default 100; `OPACITY_LIMITS` in `blocks.js`), one undo step per gesture. The background image: one `background image` row (a 14px thumbnail, the label, the file name or `none` / `empty`). Click it to pick from the library's media in a popover (`openMediaPicker()` in `popover.js`: newest first, thumbnail + name, `✓` on the current one); or drop a media item (image or SVG) from the library on it (`data-drop-media`). The `×` link removes it. When set, a `fit` toggle follows: `cover` (default) | `contain`. Hovering the row outlines the board/group edge. `empty` = a slot without media (preset, deleted item), drawn as a gray placeholder. Click a row to open the color picker popover (library colors and palettes plus a hex input). A library color can be dropped on a row. Every change affects only that one thing. **Hovering a row outlines in the preview exactly what it controls** (see "What-will-change outline" below). The vector's layers are not shown as rows in the layers tree; they live only in this section.
- **Typing exact numbers:** every number in the properties (the value at the right end of each slider row: `gap`, text `size`, vector/image `width`, board `radius` / `width` / `height`, `padding` / `margin` and their per-side rows, `offset x` / `offset y`, `rotation`, `tracking`, `line height`, text wrap `width`) can be **double-clicked and typed**. It becomes a small input (digits only, selected; a slider whose range goes below 0, i.e. the offsets, rotation and tracking, also accepts one leading `-`; a decimal slider, i.e. line height (`sliderRow(..., { decimals: 2 })`, step 0.01, shown as `1.20`), also accepts one `.`); Enter or clicking away applies it clamped to that slider's own min/max (gap 0–120, text size 8–200, width 20–360, padding 0–200, margin 0–200, offset −200–200, radius 0–120, board width/height 100–1600, group width/height 20–1600, opacity 0–100, palette width 40–1600 / height 20–800, rotation −180–180, tracking −200–1000, line height 0.8–3.0, wrap width 40–1600), Esc, an empty box, a lone `-` or non-digits cancels. One undo step per typed value. All of them share one `sliderRow()` in `properties.js`, so new sliders get this automatically. (Other values are already typeable: text content is an input, colors have a hex input in the picker; family/weight/direction/align are choices, not numbers.)
The groups below are listed in their on-screen order.
- **text** (text blocks and palette blocks; collapse key `text`). **Palette block** → `hex labels` (`off` | `on`, default on) and `names` (`off` | `on`, default off; a section only shows a name when its color came from the library), both `modeRow()`s. **Text block** (`textBody()`), top to bottom:
  - the **text box**: a `<textarea>` (it holds line breaks; one row per line of text, max 4, then it scrolls with the app's shared 6px scrollbar, not the Windows one; `data-block` so the on-board editor keeps it in sync), live, one undo step per edit; Enter leaves it, Shift+Enter is a new line;
  - the `font` row: a family button with ▾ (opens the family picker, the built-in fonts included) plus the weight/style selector for exact weights (`400`, `700`, `400 italic`; disabled when the family has one file). A deleted font shows `missing ▾`. A library font can be dropped on the row (it changes only this block);
  - one line with **`B` / `I` / `U`** (a joined row of independent toggles, `toggleSeg()`) and the **alignment** icons `left` | `center` | `right` (`segmented()`). **B** switches to the family's bold FILE (`boldTarget()` in `fonts.js`: weight ≥ 600 (`BOLD_MIN`) nearest to 700, same style) and back (the non-bold file closest to 400, same style); it shows "on" while the font's weight is ≥ 600. **I** switches to the other style's file at the nearest weight (`italicTarget()`). Each is **disabled when that file doesn't exist** (no faux bold/italic; the built-in fonts have no italic). **U** toggles `underline`, always available;
  - `size` (font size, 8–200), `tracking` (−200–1000, thousandths of an em), `line height` (0.8–3.0, two decimals);
  - `case`: `none` | `UPPER` | `lower` | `Title` (`modeRow()`);
  - `wrap`: `fit` | `fixed` (`modeRow()`); when fixed, a `width` slider (40–1600) follows. Switching to fixed starts at the text's current rendered width (measured, clamped to 40–1600).
  (The text color is in the colors group. There is no per-character kerning.)
- **transform** (content blocks: text, vector, image (not while fill is on), palette; collapse key `transform`; `transformBody()`): a `rotation` slider (−180–180°, default 0) and a `mirror` row with two independent icon toggles (`icon('flipH')` = mirror left↔right, `icon('flipV')` = mirror top↔bottom; "on" = accent). Visual only, combined with the offsets (section 7, "Spacing").
- **size** (collapse key `size`): **board** → a `fixed` | `dynamic` segmented toggle (`dynamic` is disabled with the tooltip "add content to the board first" while the board has no visible content), a `radius` slider (0–120, default 8; the board's corner radius, placed here for now), and, only when fixed, `width` and `height` sliders (100–1600). Dynamic → fixed fills width/height with the board's current rendered size. **Group** → a `width` mode row (`fixed` | `fit` | `fill`), its `width` slider (20–1600) only when fixed, the same for `height`, then `radius` (0–120). Switching an axis to fixed keeps the group's current rendered size. **Vector** → a `width` slider (20–360); a vector with no media also shows "no media: drop one from the library". **Image** → a `fill` row (`off` | `on`), then the `width` slider (20–360) only while fill is off. **Palette** → `width` (40–1600, default 320) and `height` (20–800, default 64) sliders, a `horizontal` | `vertical` segmented toggle, then `radius` (0–120, default 8). (Padding moved to the spacing group.)
- **spacing** (every item except a fill image; collapse key `spacing`): **board** → `padding` (0–200). **Group** → `padding` (0–200), then `margin`, `offset x`, `offset y`. **Block** (text, vector, image, palette) → `margin` (0–200), then `offset x` and `offset y` (−200–200 each). Padding and margin each show ONE slider by default (all four sides the same). A **link toggle** (`.icon-toggle.link-toggle`, 22px, chain icon `icon('link')` / `icon('unlink')` in `util.js`; "on" look = linked) at the end of that row splits it into four sliders labeled `top`, `right`, `bottom`, `left`; the toggle then sits at the end of the `top` row. Toggling back to linked sets all four sides to the top value. The linked state is saved per item (`paddingLinked` / `marginLinked`). Every other row of the spacing group ends with an equal empty 22px slot (`.link-slot`) so all its sliders end at the same x. `sidesControl()` / `spacingBody()` in `properties.js`. Toggling is one undo step.
- All sliders are `sliderRow()`s (double-click to type, clamped to their own range, one undo step per gesture). Each selected item's section has its own groups.
- **layout** (canvas/group, or the container around a selected block): `stack` | `row` segmented toggle, align (start/center/end) on the same line as **icon buttons with tooltips** (`start`, `center`, `end`; three horizontal lines when the layout is a stack, three vertical bars when it is a row, since align then means vertical), `gap` slider (0–120px).

**What-will-change outline (`outline.js`).** In the accent color (`--accent`), the preview outlines the exact thing a color or font will change, not the whole block. It is shown while a library **color or font is dragged over a target** and while a **color row in the properties panel is hovered**. Text → a stroke around each character (`-webkit-text-stroke` + `paint-order: stroke fill`, so the fill stays visible; class `.pick-text`). Vector layer → a temporary copy of that layer placed right after it with all fills removed and every shape stroked in the accent color, so it follows the shapes of that layer only (`.pick-layer`). Canvas background → a frame just inside the board edge, following its corner radius (`.pick-bg`, `border-radius: inherit`). Group background → the same frame on the group (`{ type: 'group', blockId }`, `.block-group.pick-bg`). Palette section → a 3px frame just inside that one section (`{ type: 'section', blockId, section }`, `.pick-section`). The appearance group's background image row outlines the same edge. The old whole-block dashed `.drop-target` box is no longer used for color or font drops on the preview. The outline only decorates the live preview DOM (CSS classes and one temporary clone) and is removed when the drag/hover ends; the export builds its own DOM, so the outline can never appear in an export.
- **Several items selected:** the properties area shows **one section per selected item, stacked** (separated by a divider), each under a small header naming it (`Board 1` for a board, `Board 1 / heading 1` for a block). With nothing selected the area says "select a board or a block to edit it". Each section is that item's normal groups (in the fixed order) and every control only edits the item of its own section. Group collapse state (by group name) is shared by all sections. The properties area scrolls inside itself when long; the layers header above and `save as preset` below stay put.
- Bottom: dashed `save as preset ▣` button (asks for a name in a small inline input). **Enabled only when exactly one board is selected** (a selected block no longer enables it; tooltips "save this board structure as a preset" / "select exactly one board").

## 9. Drag and drop

Uses native HTML5 drag and drop. The drag payload is `{ kind: 'font'|'color'|'media'|'block'|'preset'|'palette'|'node', id }` (`node` = a row of the layers tree; `palette` = a whole library palette card; `font` id = a specific library font file; `block` id = the block type name). Sources carry `data-drag-kind` / `data-drag-id`; `dragdrop.js` plans each drop (`planDrop`) and runs a single `state.js` call.

Drop targets and results:
| Dragged | Dropped on | Result |
|---|---|---|
| block type | empty dot grid | if `canvas`: new empty canvas (fixed 160×160). Otherwise: new **dynamic** canvas containing that block (a `group` = an empty library group; groups only live inside boards) |
| block type | a canvas / group | adds the block to it (at the drop position in the flow); a `group` is added EMPTY |
| preset | empty dot grid | new canvas (`Board N`) from the preset structure (placeholders), with the preset's size mode, width/height, padding and radius |
| media | empty dot grid | new **dynamic** canvas containing a vector/image block with that media item (added in the canvas-size pass) |
| media | a canvas | adds a vector/image block with that media item |
| media | a vector/image block | swaps its media item |
| palette (a whole library palette card) | empty dot grid | new **dynamic** canvas containing a palette block with copies of its colors (named after the palette) |
| palette (a whole library palette card) | a canvas / group (or a layers row: into a board/group row, after a leaf row) | adds a palette block with copies of its colors (hex + name) at the drop position in the flow; later edits of the library palette don't change it |
| color | one section of a palette block (the section under the pointer) | sets just that section's color and stores the library color's name (outline: a frame inside that section) |
| font | empty dot grid | new **dynamic** board (`Board N`) containing one heading block (`heading 1`, normal heading defaults) in that font (the card's weight, closest to 400) (`addFontHeadingToNewCanvas()`) |
| font | empty space inside a board / group (preview only, not on top of a block) | adds a heading block in that font at the drop position in the flow, named `heading N` (`addFontHeading()`). On top of a vector, image (fill images too) or palette block: nothing. Layers-tree board/group rows: nothing |
| font | a text block (preview or layers row) | sets that block's own font. If the block is one of **several selected text blocks**, it sets the font of ALL selected text blocks (one undo step) and every one of them gets the accent text outline. Dropping on an unselected block changes just that block |
| color | a canvas background area | sets that canvas's `background` (outline: the canvas edge) |
| color | empty space inside a group | sets that group's `background` (outline: the group edge) |
| color | an image block (fill or not) | sets the background of the image's container: its group, or the board (outline: that edge) |
| media | the `background image` row of a board/group in the editor | sets/swaps that board's/group's background image (outline: its edge). Dropping media on a board/group in the preview still adds a block |
| color | a text block | sets that block's `color` (outline: the text) |
| color | a vector layer (the shape under the pointer) | sets just that one layer's color (outline: that layer's shapes). Empty space inside the vector is not a target |
| color | a row in the editor's colors section | sets that row's one thing (outline of it in the preview) |
| color (library color card, or a swatch of another palette) | a palette card in the library | adds a COPY (name + hex, new id) at the insertion line (left/right half of a swatch = before/after it); on the name, empty space or `+` tile: at the end. Duplicates allowed |
| palette swatch | its OWN palette card | moves (reorders) it to the insertion line; no copy. Dropping it on its own spot does nothing |
| anything | a row in the layers tree | same as dropping on that node in the preview |

Additions beyond the table: a `canvas` block dropped on a canvas adds a new canvas after it; a preset dropped on any canvas also makes a new canvas; a media item dropped on a vector/image block only swaps if the types match (svg↔vector, image↔image), otherwise it is added to the container; a font can be dropped on the `font` row of a text block's section in the editor (changes only that block); which background a color dropped on a group/image/canvas changes is decided by `backgroundTargetOf()` in `state.js` (used by `dropColor()` and for the outline). Layer-row drops: `node` rows reorder/move, `block`/`media` on a leaf row insert after it; a color on a text row sets its color, on a group row sets that group's background, on an image row sets its container's background, on a canvas row sets the canvas background, and on a vector or palette row does nothing (several layers / sections: drop on one in the preview or in its colors section; `dropColor()` ignores palette blocks too, sections are set by `setSectionColor()`). A palette card dragged over another palette card in the library does nothing (only colors drop there). The outline is the hovered valid target only (`.drop-target`, or `drop-into/before/after` on tree rows; a palette card gets `.drop-target` plus the insertion line, carried in the plan as `insert`, and a reorder shows the `move` drop cursor). **Color and font drops on the preview use no box at all**: a plan carries `outline` (`{type:'text'|'layer'|'canvas'|'group'|'section', …}`; text takes `blockId` or `blockIds: [...]` for several blocks at once) and `el: null`, and `outline.js` draws the accent outline of exactly what will change (see the editor section). Tree rows and editor rows keep their own drop highlight in addition to the preview outline. Dropping files from Explorer onto the window is ignored (use `+ import`).

Show a lime dashed outline on valid drop targets while dragging. Every drop is one undo step.

## 10. Export

- Exports **all visible boards** as laid out in the auto grid (at 100% zoom, ignoring current pan/zoom, at their real sizes and corner radius, with every padding, margin and offset (per side included), every group (background, radius, sizing modes, clipping), fill image, background image, block opacity, rotation/mirror, text styling (tracking, line height, alignment, case, underline, wrap, line breaks), palette block and color alpha (rgba) exactly as in the preview, since both use the same `renderCanvasElement()`, in the same column/row cells as the preview via the shared `applyGridLayout()`), with each board's **name** as its label above it when `board labels` is on (off: the labels and the row they take are left out; board sizes are unchanged). With nothing to export the notice says `nothing to export: add a board first`.
- Rendered with **html-to-image** from an offscreen export container at `pixelRatio = scale`.
- **PNG** or **WebP** with transparent toggle on: the dot grid and app background are excluded; boards keep their own backgrounds, and the area outside a board's rounded corners is transparent. **JPEG**: always on a solid background.
- **WebP**: html-to-image has no WebP function, so the sheet is rendered with `htmlToImage.toCanvas()` and encoded with `canvas.toDataURL('image/webp', 0.92)` (Chromium's built-in encoder; no extra package). Save dialog uses a `.webp` filter.
- **Style labels** checked: append a strip below the canvases listing, for everything used: a **colors** section with a small heading per board showing **the board's name** (`Board 1`, or its renamed name) followed by one entry per colorable thing, each shown as its name plus the color chip(s) and hex(es) it uses **right now**: `background`; every visible group with a background color, by its name (e.g. `group 1`; transparent groups are left out); every visible text block with text and a font (by block name, e.g. `title`, in its current color, black by default); and every first-level layer of every vector (`<vector name> / <layer name>`; a layer still on its original colors lists every color it contains, a recolored layer its one color); and every visible palette block as ONE entry under its own name, listing all its sections' colors in order. A hex that matches a library color/palette swatch also shows that name. A color with alpha shows its percentage after the hex (`#D9FF43 · 40%`) and its chip has the small checkerboard behind it; opaque colors look as before. Then each font written **in its own typeface** with family + weight; each media item's name next to a **one-color black version** of it (section title `media`; this includes media used as a board's or group's background image, and fill images).
- The style-labels strip keeps its per-board name headings even when `board labels` is off, so options can still be told apart.
- After rendering, `window.api.saveExport()` opens a save dialog (in the last export folder, see section 6) with a default name like `stylesheet_export_2026-10-07.png` (`.jpg` / `.webp` for the other formats).
- Imported fonts must be embedded in the export (make sure html-to-image can fetch them through `ssfile://`).

**As built:** the offscreen sheet is built into `#export-root` by `export.js` using the same `renderCanvasElement()` and `applyGridLayout()` as the preview (no selection outline, no shadow). Because dynamic canvases size themselves, the grid is laid out first and, after `document.fonts.ready`, the style-labels strip is made exactly as wide as the measured grid. The sheet has 24px padding; background is white for JPEG or when transparent is off, transparent otherwise (the style-labels strip is always a white card). `html-to-image` is called with `pixelRatio: scale` and a hand-built `fontEmbedCSS` (every used library font fetched through `ssfile://` and inlined as a data URI, plus the bundled IBM Plex Mono 400/500/700 and Space Grotesk variable files via `window.api.readBundledFont`), because a `file://` page cannot `fetch()` its own font files. The strip's colors section is built per canvas by `collectUsage()` (see above; original layer colors come from `layerInfo()`), each used font as `Family weight` in its own typeface, and each used media item as a black one-color version (rasters use `filter: brightness(0)`). `transparent` stays stored while JPEG is selected; the toggle just shows disabled/off.

## 12. Gotchas to remember
- Frameless window: buttons inside the drag region must be `-webkit-app-region: no-drag` or they won't click.
- Illustrator often puts fills on paths or in a `<style>` block with classes. Never guess a shape's color from its attributes: mount the SVG and read `getComputedStyle` (that is how `svg.js` finds original colors and which shapes have a fill/stroke). To recolor a layer, set inline `fill`/`stroke` only on the shapes that really have one, so `fill="none"` shapes stay unfilled.
- The accent "what will change" outline must stay out of exports: it is only ever added to the live preview DOM by `outline.js`; the export renders from its own fresh DOM. The same goes for the preset-save ripple (a temporary `.ripple-canvas` in `#stage`, never inside a board) and the accent text selection/caret while editing on a board (only on the live `.editing` element).
- Font samples written in their own typeface (library `Aa`, font picker names, export font lines) must go through `fitFontSample()` in `fonts.js`: some fonts draw far outside their font-size/line box. It measures with a canvas, so the font must already be loaded (registered fonts are; `syncLoadedFiles()` in `app.js` redraws when a new one finishes loading).
- Register imported fonts with the `FontFace` API using `ssfile://` URLs, and wait for `document.fonts.ready` before export.
- `position: sticky` breaks inside `overflow: hidden` ancestors — use flex layouts for panel headers.
- Decorative pseudo-elements need `pointer-events: none`.
- Save on quit: block the quit until the renderer confirms the session flush (with a short timeout fallback).
- Drop handlers must run the planned action **before** clearing the drag payload (the planned closures read the dragged id lazily).
- Restoring from trash: wait for the main-process trash sync (`whenTrashSynced()`) before reloading the file, or the read races the file move.
- Font table offsets differ by format: in a TTF/OTF directory entry the offset is at +8, in WOFF at +4.
- `html-to-image` copies the root's computed styles, so the offscreen export node must be `position: static` inside an off-screen wrapper (not itself positioned off-screen).
- A `file://` page can't `fetch()` local files; use `ssfile://` (library files) or a `window.api` call (bundled fonts).
- Dynamic canvases size from their content, so any code that needs a canvas's or the grid's size must **measure the DOM** (`offsetWidth/Height`, which ignore the zoom transform) after it is laid out, not compute it from data. The grid needs `width: max-content`, or the window width squeezes dynamic canvases and wraps their text.
- Every canvas must have `size`, `padding` and `radius`; `fixEmptyDynamicCanvases()` and the renderer read them without checks. `createCanvas()` guarantees them for every new canvas, and old-format data is never loaded (section 6), so there is no upgrade path to keep in sync.
- The `.bg-layer` (background image + fill images) sits at `z-index: -1`. That only works because `.canvas` and `.block-group` are `isolation: isolate`; without it the layer would drop behind the board/group's own background color (or behind the whole page).
- Fill (group sizing) only means something against a definite parent size. The renderer decides that in JS (`groupSizing()` passes `defW` / `defH` down) instead of trusting CSS, because a stretched or `flex: 1` item inside a shrink-wrapping parent would size itself to its siblings, not behave like fit. The same place gives an empty group 160px on an unresolvable fill axis.
- Visible text must say "board", but ids, classes, types and function names keep "canvas" (see the note at the top). Renaming an id or class to "board" would break `dragdrop.js`, `outline.js`, `eyedropper.js` and the CSS that look them up.

## 13. Decisions made where the spec was silent (assumptions log)

Add to this list whenever a new assumption is made.
- Fonts are stored as font **ids** (not family names) because the picker chooses weight/style too. Default weight = closest to 400. (Per-block now, see "Fonts" in section 7; this replaced the old per-canvas font roles in the font pass.)
- **Canvas-size pass assumptions:** "Has content" = a visible block of any type or a visible group that shows something; a canvas whose only blocks are hidden is empty. Dynamic → fixed stores the measured size **unclamped** (a dynamic canvas smaller than 100 or bigger than 1600 keeps its size; the slider just shows its end until moved). A hidden canvas isn't measured; switching it to fixed uses its stored width/height. Dynamic canvases still store width/height (160×160 by default) but don't use them. The size group sits after layout so the existing groups don't move. Slider labels are `min-width: 44px` instead of a fixed 44px (your choice), so `padding` widens its own label column instead of overlapping its slider; its track starts a little further right than the other sliders. Dropping media on the empty grid didn't do anything before; the brief listed it, so it now makes a dynamic canvas containing it. `+ block` with nothing selected also makes a dynamic canvas (it goes through the same `addBlockToNewCanvas()`). The 160×160 fallback also applies on load (a saved dynamic canvas with no content).
- **Replaced in the font pass:** text blocks always render, in their own font (Space Grotesk by default; a deleted library font also falls back to it). New text starts as its type name; cleared text shows the type name at 40% opacity. Preset blocks start with the type name as text. (The old gray text placeholder is gone.)
- **Font pass assumptions (mine, from your answers):** the built-in fonts are Space Grotesk (the default, changed from IBM Plex Mono at your request; it's the variable file, offered at 400/500/700) and IBM Plex Mono at 400/500/700; they live in code (`BUILTIN_FONTS`), not in `library.fonts`, so it never appeared in the library panel (they do now, as undeletable cards) and can't be deleted, but it is in every font picker. The `none` row is gone from the font picker (a block always has a font). Double-click focuses the text box with the text selected (so typing replaces it). Dropping a font on a selected text block changes the *directly selected* text blocks only (not text inside a selected group); dropping on the `font` row of a section changes just that section's block. Export always embeds IBM Plex Mono 400/500/700 and the Space Grotesk variable file.
- Library deletes: colors/palettes/presets are never "in use" (they hold copies). Deleting a font deletes the whole family. Palette-swatch deletes are trashed as `palette_color` and can only be restored if their palette still exists.
- Undo history includes the library (so deletes undo). Importing a file can be undone, but the copied file stays on disk (harmless; redo reuses it).
- "Clear boards" = remove all boards and leave one empty `Board 1` (fixed 160×160, #EDEDEE, radius 8). (A first launch, by contrast, has no board at all.)
- "Default export scale" in settings is `session.export.scale` (one value shared with the export bar).
- Board names auto-increment to the first free number (`Board 1`, `Board 2`…, no upper limit; this replaced the `lockup_A` … `lockup_Z` letters).
- The grid re-fits when the visible canvas count changes; `fit` caps at 100%.
- Layout shown in the editor for a selected leaf block is its parent container's (group or canvas).
- Color/palette names are slugged to `lowercase_with_underscores` when edited.
- Media cards show a lime border when any block uses that media item.
- The library's data key, folder, drag kind and block field are all called `media` (`mediaId`); the *block types* `vector` and `image` keep their names.
- Block second-line labels (`text`, `media`, `container`, `color`, `layout`) are my wording; edit `kind` in `BLOCK_TYPES` to change them.
- The `drag in` hint now appears only on the blocks header (media and fonts show `+ import` instead).
- Palette swatch size (26px) and hue bucket size (15°) were chosen by me; both are single constants in `library.css` / `sorting.js`.
- Maximize happens in `ready-to-show` right before `show()` (calling `maximize()` on a hidden window would show it early). The saved setting wins over any remembered size; there is no remembered window bounds.
- `settings:save` sanitizes its input in `main.js` (anything but `windowed` becomes `maximized`), so a bad file or call can't break startup.
- The editor's weight/style `<select>` is not a button, but it gets the accent border on hover to match its neighbors.
- Pressed-button background `#0C0C0E` and the 80ms transition are my choices (a slightly darker `--card`).
- The old top "click anywhere or press Esc to close" line in the help overlay was folded into the new bottom footer line (one line, not two).
- `+ block` copies the settings `close` button's style by reusing `.link-btn` (which has no press state), so it has no press effect; it was originally a `.link-btn` and the 20px compact header fits it again.
- Align icon glyphs are my own drawings (3 lines / 3 bars, 1.3 stroke like the other icons); `row` direction swaps to the vertical-bar set.
- Overflow audit (static, by measuring widths, not visually) at 1280×720: nothing was found overflowing. The colors section rows are single full-width rows (no 2×2 grid any more), with the layer name truncated by an ellipsis.
- The joined segmented toggles are made of overlapping bordered buttons (not a bordered wrapper) so the selected accent border can sit exactly over a divider.
- Help cards (your spec): max 330px, 24px gaps, content-height cards with aligned tops; at 1280 they are 290px wide (4 cards + 3 gaps + 24px side margins). My choices: the import tips column headings are white (`--text`) 11px uppercase so they don't compete with the accent `IMPORT TIPS` title; the columns are 24px apart; the small-window fallback is a measured check (`.compact` class) rather than a fixed media query, so it only kicks in when the box would actually touch the footer (measured since the help rewrite: `.compact` applies at 1280×720, together with the move-up, see 8.9). The compact values (9px 12px padding, 11px text) are mine. The check runs once when the overlay opens, not on resize.
- Wheel zoom listens on the whole `#preview` panel (so the floating bars don't block it) but only the canvas grid is scaled; the 1.1-per-100px rate and the ±300 delta cap are my choices. Typed zoom has no `%` sign in the input and allows at most 3 digits; "center of the preview" means the center of the stage area (`stageCenter()`), not the visible gap between the floating bars.
- The empty-state button replaced the old "drag a preset or a block here to start" text entirely (the text is gone).
- The zoom `100%` readout is a non-clickable middle segment of the joined zoom control.
- **Per-item colors:** new canvases are white (since the first-run defaults pass: #EDEDEE), new text is black, new vectors show the file's own colors (your decisions). The `swatch` block was removed (your decision).
- First-level layer = drawable direct child of the SVG root, with one assumed extra rule of mine: a single wrapper group holding several drawable children is skipped (Illustrator's usual `<g id="Layer_1">`). Layer key = its index (0, 1, 2…), which is stable because an imported file never changes.
- Original colors are read via `getComputedStyle` on an off-screen mount; a gradient's "color" is its first stop; fully transparent colors are ignored. Shapes inside `<defs>`, `<clipPath>`, `<mask>`, `<pattern>`, `<marker>` are never repainted, and a `<use>` of a `<symbol>` only gets the fill on the `use` element, so symbol content that declares its own fill keeps it (rare).
- Recoloring sets inline fill/stroke, so a stylesheet rule with `!important` could still win (rare in Illustrator exports).
- The vector outline is an accent stroke (2px, non-scaling) on every shape of the layer, including inner details, not a single merged silhouette; the text outline is a 3px glyph stroke (outer half visible). Both widths are single values in `preview.css`. The canvas outline is a 3px frame just inside the edge.
- Dropping a color on empty space inside a vector, or on a vector row of the layers tree, does nothing (there is no single layer to change). Dropping on an image/group sets the canvas background.
- Swapping a vector's media (dropping another SVG on it) resets all its layer colors to the new file's originals.
- The colors section group is saved under `collapsedGroups.colors`.
- Export style labels list a text block only when it has text (a cleared block shows only a faded type name, so it isn't listed). Block names are used as labels, so rename blocks to make the strip clearer.
- **Multi-select (your decisions):** the selection is a list and is either blocks in one canvas or canvases, never a mix; a conflicting pick switches the selection to just that new item (changed from "becomes the owning canvases" after testing: that could delete canvases by accident). A canvas is outlined only when it is itself selected. `+ block` adds to the end of the selected canvas(es); the `group` block was removed from the library and `+ block` in the group pass (groups were made in the layers tree only), and came back as an empty library group in the group block pass (see the end of this list).
- **Group pass assumptions (mine, from your answers):** the `group` node type stays in the data (presets, preview, drag-into-group all use it); its icon `▢` lived in `GROUP_GLYPH` in `blocks.js` while it wasn't in `BLOCK_TYPES` (it is back in `BLOCK_TYPES` since the group block pass). A new group takes the parent's layout; empty groups were auto-removed (no longer, since the group block pass); grouping blocks that sit in different parents puts the group at the first one's spot and pulls the rest in. Ungrouping a mix of groups and non-groups only affects the groups. Dragging a multi-selection in the tree still moves just the dragged row.
- **Drag-select assumptions (mine):** the box selects what it *touches* (not only what it fully contains); a drag may start on empty grid, a canvas or a block (blocks can't be dragged on a canvas); movement under 4px still counts as a click; the box ignores Ctrl/Shift; the selection updates live while dragging.
- **My assumptions for multi-select:** Shift+click in the preview works like Ctrl+click (toggle); in the tree Shift+click replaces the selection with the range (it does not add to it) and keeps the anchor. A modifier-click on empty dot grid does nothing. Ctrl-clicking a block while a canvas is selected selects just that block. After `+ block` or paste into several canvases, those canvases stay selected (blocks in different canvases can't be). Right-click menu and `Ctrl+C/V` exist in the layers tree only (not the preview). Delete from the menu has no confirm (undoable). Board copies/pastes use the first free number (`Board N`), not "copy". Bunching: dots move along the surface slope, up to 5px radially toward the nearest crest (= away from a trough). Splash: an accent glow at the center, 6→52px, fading over 420ms (drawn over the dots, under the boards). The wave distances are on screen (not scaled by zoom), so it looks the same at any zoom; the droplet stays on the board's world position if you zoom/pan while it plays (the still grid is redrawn for the new view). A dot is only touched when its wave height is at least 2%. The canvas draws the dot like the CSS one (solid 1px radius, 0.2px soft edge, read from `--dot`/`--bg`/`--accent`); at a fractional zoom the browser may place CSS dots up to a fraction of a pixel differently, which isn't visible. At very low zoom (many dots) a big ripple is more work per frame; it is still drawn with one image copy per moving dot.

## 14. Dev and testing notes

- `npm start` runs the app; `npm run dist` builds `dist/Stylesheet_-Setup-<version>.exe` (NSIS, unsigned, so SmartScreen warns: "More info" → "Run anyway"). Packaged-app smoke test: `dist/win-unpacked/Stylesheet_.exe`. `npm run icon` regenerates `build/icon.ico` from `build/icon.svg`.
- **`npm start` and the installed app share ONE data folder** (`%APPDATA%\Stylesheet_`, from the productName). A dev launch therefore reads and writes the installed app's library/session. Use `STYLESHEET_USERDATA` for any test run, and to see the first-launch experience delete `%APPDATA%\Stylesheet_` (or point `STYLESHEET_USERDATA` at an empty folder). Uninstalling does not delete that folder. Data saved by v1.1.0 or older (no `dataVersion`) is moved into `old-data-backup-<date>/` on the first launch of this version; current data (version 2) is never backed up.
- **Data housekeeping (Robert's rule, see sections 2 and 6):** one copy of Robert's data, no versions. At the end of every change, ask Robert whether to delete `%APPDATA%\Stylesheet_` (delete only on a yes, after looking at it; make sure the app isn't running). Run every automated test with `STYLESHEET_USERDATA` pointing at a throwaway folder in TEMP, and delete those folders when testing is done, so no extra copies of app data are left on his PC.
- **Testing the wipe:** point `STYLESHEET_USERDATA` at a throwaway folder holding a `library.json` / `session.json` without `dataVersion` (and a `library/` folder): the app should log `old data moved to …`, open like a first launch, keep `settings.json`, and a relaunch must not make a second backup. (Done in the boards pass: old files and `library/fonts/old.ttf` landed in the backup folder, defaults were installed, the saved files carried `dataVersion: 2`, and a relaunch kept `Board 1` / `Board 2` with no new backup.)
- **Releasing a new version:** bump `version` in `package.json` (the status bar and settings read it; `package-lock.json`'s top two `version` fields should match), commit in GitHub Desktop, then `npm run dist`. The installer upgrades an existing install in place and keeps the user's data.
- If Electron launches as plain Node ("Cannot read properties of undefined (reading 'setPath')"), the shell has `ELECTRON_RUN_AS_NODE` set; unset it.
- **Dev-only environment variables** (honored only when the app is not packaged, except `STYLESHEET_USERDATA`): `STYLESHEET_USERDATA` (use a throwaway data folder; keep the path short, long paths break Chromium's cache), `STYLESHEET_DEBUG=1` (print renderer console messages to the terminal), `STYLESHEET_HARNESS=<file.js>` (a test harness that receives `{app, win, ipcMain}`), `STYLESHEET_IMPORT=<path;path>` (skip the import dialog), `STYLESHEET_EXPORT_PATH=<file>` (skip the save dialog). Test harness scripts are kept outside the repo.
- Automated checks done so far were scripted launches (screenshots, simulated drag events, close/reopen, export, trash flows, DOM measurements of the panel splits and help fit at 1280×720 and 2048×1152, first-run contents). Robert has looked at the first-launch experience in dev. Real mouse/keyboard dragging, native file dialogs and the v1.0.0 installer have not been verified by automated tests.

## 15. Status (v1.2.1) and known limitations

All eight build phases are implemented, plus the later passes logged in section 13 (multi-select, groups, eyedropper, notification log, glass panels, canvas size/padding, labels above canvases, equal library sections + 60/40 editor split, final app icon, first-run defaults, help rewrite). Version 1.0.0 was the first public release (all test data was deleted before building it, so the first install started as a new user). **v1.1.0** adds the library section expand button + search. **v1.2.1** (the version in package.json now; not yet built or released) adds everything since: canvases are called **boards** on screen, named `Board 1, 2…` with their names as labels, have a corner radius, per-side padding / margin and offsets live in a spacing group (property groups in a fixed order), the spacer block is gone, groups are a library block with backgrounds, fixed/fit/fill sizing, padding and radius, images can fill their parent, boards and groups can have background images, every block has an opacity, every color can carry an alpha (`#RRGGBBAA`), a palette block can be added (or made by dragging a library palette card), content blocks rotate and mirror, text is edited in place on the board and has B/I/U, tracking, line height, alignment, case and wrap, presets keep all block structure but no content, and data from v1.1.0 or older is backed up and replaced by a fresh start (`dataVersion` 2, never bumped again; all old-save upgrade code removed). Robert keeps one copy of his app data and is asked after every change whether to delete it. Known gaps: variable fonts act as one weight; WOFF2 metadata comes from the file name; the editor properties area scrolls inside itself when long (many vector layers, or several stacked sections when many items are selected); the installer is unsigned.
